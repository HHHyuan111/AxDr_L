## 2. 架构铁律

### 2.1 依赖方向（唯一铁律）

> **只允许向更低层 include；同层之间禁止横向 include（最底层内部除外）。**
> 违规 = 构建检查直接失败，不是代码评审问题。

七层定义（v2 目标架构）与实际仓库目录的对应：

| 层 | 职责 | 实际目录（AxDr_App/User） |
|---|---|---|
| L0 core | 纯算法：类型、PID/滤波/轨迹/SVPWM/查表三角/观测器核 | `algorithm/`、`diagnostic/core/`（mc_*）、`control/` 中的纯核 |
| L2 chal | 芯片抽象：PWM/ADC/SPI/正交/flash/时基/临界区 | `bsp/` |
| L3 device | 设备适配：传感器读数、**整数↔物理量换算只在此发生** | `adapter/`（encoder/position/speed） |
| L4 domain | 电机域：数据模型、Drive 状态机、控制壳、任务链 | `motor/`（common.h 即 foc_t 聚合体）、`drive/`、`control/`、`app/` 引擎部分 |
| L5 service | 对外协议、参数存储、遥测 | `service/`（axdr_*、service_*） |
| L6 app | 组装与入口：main、ISR 分发 | `app/`、`main.c` |
| 配置 | 参数值、默认档案、flash 存储 | `config/` |
| 公共头 | 类型、常量、薄适配 | `common/`、`motor/common.h` |

关键推论：

- **算法核（L0）不得 include 任何 STM32 HAL/板级头**——grep `hal_|stm32` 自查。
- 板级差异全部收敛在 `bsp/` + 板级配置；上层代码两块板之间零改动。
- 同层协作走数据模型（foc_t 字段），不走互相调用。

### 2.2 八个插槽：新代码唯一入口

| 插槽 | 接法 | 换 X 时只动 |
|---|---|---|
| ① 控制器 | 环接口（输入给定+反馈，输出电压） | 算法库核 + 控制层壳 + 配置 |
| ② 传感器 | sensor 接口（read_raw，上层统一算速度/多圈） | 适配层实现 + 装配一行 |
| ③ 命令源 | 门面 API（request / set_target / param_get_set） | 协议命令表 / 按键映射表一行 |
| ④ 配置 | motor_cfg_t + 默认档案 + flash（版本+CRC，读败回默认） | 换电机只加一个档案，零代码 |
| ⑤ 保护 | 保护函数 + 错误位图，登记进保护表 | 保护函数 + 错误位 + 阈值配置 |
| ⑥ 遥测 | debug_snapshot 只读快照字段表 + 帧表 | 字段表加一行 |
| ⑦ 模式 | 模式表（每拍放行判定） | 模式表加项 + 编排函数 |
| ⑧ 板级 | bsp 七模块函数族（pwm/adc/spi/qenc/flash/time/osal） | 每板一份实现 |

**三问模板**（加任何新代码前自答）：核放哪？→ 算法库。谁每拍调它？→ 控制层壳或传感器包装。用户怎么选它？→ 配置/装配/命令表，**只能选一处**。

**反向纪律**：新代码要动 ≥2 个插槽才能落地 = 在破坏架构，停下来先讨论接口，不要硬写。

### 2.3 全局状态

- **唯一允许的顶层单例：`g_foc`**（foc_t，电机实例聚合体）——每个字段有**唯一写者**，在字段注释标注生产上下文。
- 其余一切可变状态必须进结构体上下文（函数首参对象指针）。**禁止新增任何散装可写全局变量**。
- 模块私有对象/函数一律 `static`。
- 跨上下文共享数据三规则：单字段 32 位 float 直读直写（M4 原子）；成组字段用一次快照拷贝；命令类写入走临界区（<1µs）。

### 2.4 并发上下文（每个函数声明所属上下文）

| 上下文 | 触发 | 允许 | 禁止 |
|---|---|---|---|
| RT | ADC JEOS 中断，20kHz | 快环任务链 | flash 写、SPI 长传输、printf、任何阻塞、不定界循环、动态内存 |
| MID | TIM 中断或 RT 分频，2~5kHz | 中速任务 | 同上 |
| MAIN | 主循环 while(1) | 协议解析、存储、显示、状态机请求 | 无 |

ISR 内只允许一个调用链：清 ADC 标志 → 快环分发函数。禁止 ISR 五连调、禁止注释开关切换逻辑。

## 3. 代码规范（C11）

### 3.1 排版

- UTF-8、文件以换行结束；4 空格缩进；禁 Tab 与行尾空格；单行 ≤120 字符；一行一条语句。
- **if/for/while/do 即使单条语句也必须加花括号**。
- 逗号分号后、二元操作符两侧留空格；`.`、`->`、一元操作符不额外留空格。

### 3.2 命名

| 对象 | 规则 | 正例 | 反例 |
|---|---|---|---|
| 类型 | `模块名_名_t` | `foc_fb_state_t`、`drive_pwm_cmd_t` | `lpf_t`（无模块归属）、裸 `encoder` |
| 枚举值/宏 | 大写 + 模块/类型前缀 | `DRIVE_REQ_RUN`、`ENCODER_TYPE_ABZ` | `reset/start/opera`（裸词） |
| 函数 | `模块_动作`，小写 snake_case，**公开函数必带模块前缀** | `drive_fast_step`、`service_telemetry_capture_count` | `foc_vel()`、`pos_calc()` |
| 变量/字段 | **短名**（项目惯例：简洁缩表达意），单位**不写进名字**，写在类型定义头部注释或字段行注释 | `spd_r`、`vbus`、`theta_e`（`foc_fb_state_t` 头部统一声明"电流 A、角度 rad…"） | `wm`、`vs`（量纲靠猜且无注释）；`flag` 命名 |
| 文件 | 全小写下划线，一模块一文件 | `service_observation.c` | `foc_drv.c`（混装 7 种职责） |
| 数学常量 | 沿用 `common.h` 既有宏（`M_2PI`、`div_M_2PI`、`SQRT3_BY_2`…） | — | `#define M_PI`（覆盖标准名，禁止） |

- 禁止新造第二个常量源；需要新常量时先查 `common.h`。
- 单字符变量只允许极小范围循环；布尔变量直接表达状态。

### 3.3 类型与数值

- 寄存器/协议/存储用 `<stdint.h>` 固定宽度；长度与对象大小用 `size_t`；布尔用 `<stdbool.h>`。
- `float` 字面量带 `f`；**全项目禁 double**（双精度软件模拟慢 50 倍，`-Wdouble-promotion` 报错）。
- 有符号/无符号转换、窄化转换必须检查范围；分母可能为零必须保护。
- 饱和、限幅、角度归一化、积分器边界、NaN/Inf 行为**必须定义并有测试**。
- 协议/持久化结构体用 `__attribute__((packed))` 显式定宽，不依赖填充。

### 3.4 所有权与接口

- 严禁读取未初始化变量；指针使用前建立有效性契约，可空边界显式检查。
- 只读输入 `const`；不返回局部对象地址；数组访问前验证长度和索引。
- 头文件：自包含（单独 include 必须能编译）、include guard、不定义可写对象；大型常量表 `.c` 定义 + 头 `extern const`。
- **死代码策略：删除，不是注释掉**。要保留历史用 git。
- 跨模块共享对象尽量只有一个创建者和写者。

### 3.5 宏

- 参数与整体结果加括号；实参不得含副作用；优先 `static inline`；多语句宏必须 `do { } while (0)`。
- 离散状态用枚举，固定物理常量用有类型只读对象，可调参数进参数包——**不把所有数值做成宏**。

### 3.6 控制流与错误处理（三级）

```c
/* 1) API 返回码：默认 void；只有可能失败的函数（初始化/IO/配置读写/参数设置）
 *    返回 ret_e，调用方必须检查 */
typedef enum { RET_OK = 0, RET_PARAM, RET_BUSY, RET_UNSUPPORTED, RET_IO } ret_e;

/* 2) 运行时故障：位图（检测方置位 → Drive 状态机统一停机处置 → 显式清除） */
/*    现有结构：foc_fault_t（过流/欠压/过压/过温/编码器/采样/离线/超速/PWM） */

/* 3) 编译期：配置矛盾报编译错误，不留到运行时 */
_Static_assert(BOARD_PWM_FREQ * TASK_SPD_DIV >= 2000, "speed loop too slow");
```

- `switch` 必须有 `default`，每分支显式 `break`/`return` 或注明贯穿；返回值所有路径完整。
- 禁止静默吞错误；禁止 `while(1)` 裸死循环（故障停机走状态机，不是卡死 ISR）。
- `goto` 不用于一般流程控制（主机工具单一清理路径可受控使用）。

### 3.7 注释

- 新 `.c` 文件头至少 `@file` + `@brief`；公开函数说明目的/参数单位/返回/前置条件/实时约束。
- 注释解释**为什么**和非显然约束，不复述代码；改代码同步改注释。
- **注释与提交信息统一使用中文**（项目惯例，覆盖 03 号"英文优先"条款）。
- 物理字段注释带单位与写者：`float spd_r; /* [rad/s] 由编码器适配 @RT 写 */`。

## 4. 算法模块规范

### 4.1 参数三居所

| 参数种类 | 类型定义放哪 | 值放哪 |
|---|---|---|
| 可调参数（要调/要存/上位机可读写） | 算法自己的 `.h`（cfg 结构体，只定义类型不放变量） | `motor_cfg_t` 中的一块 + **默认档案一处** |
| 物理常量（永不调） | 算法 `.c` 内 `static const` | 不存 |
| 标定/板级量 | 板级/标定头 | 配置的标定束 |

理由：持久化/上位机读写/版本迁移需要统一入口（值集中）；模块内聚要求类型跟算法走。新增参数**必须**同时落默认档案并带来源注释。

### 4.2 三件套固定模板

```c
void adrc_init(adrc_t *a, const adrc_cfg_t *cfg);  /* 清状态、存参数引用 */
void adrc_reset(adrc_t *a);                        /* 积分/观测器状态清零 */
float adrc_tick(adrc_t *a, float ref, float fdb, float ts); /* 唯一每拍入口 */
```

`tick` 是唯一每拍调用点；**所有状态在对象结构体里**；文件头注释块声明：来源/单位（SI）/调用上下文（RT 20kHz）/无动态内存/无硬件依赖。

### 4.3 提交前八条自查（逐条勾）

1. 落位正确：纯核→`algorithm/`（或 `diagnostic/core/`），控制壳→`control/`，传感器类→`adapter/`
2. 命名符合 §3.2
3. **零全局变量**：状态全在结构体，函数首参为对象指针
4. **零硬件依赖**：`.c` 不 include 任何 HAL/驱动头（grep 自查）
5. 每个字段带单位注释
6. 三件套齐全（init/reset/tick）
7. 配置类型已导出 + 默认值已进默认档案（含来源注释）
8. **host 单测 ≥1 用例 + 一条数值基准**（可用录波数据对拍）

## 5. 数值表示政策（五条，全框架强制）

1. **全局 float 单精度 + SI 单位**。禁 double；`sqrtf/sinf/fabsf`；**禁止重定义标准宏名**（`M_PI` 是已知问题）。
2. **标幺化只允许两个边界**：SVPWM 输入端（vd/vq→占空比，vbus 归一化是模块内部细节）和饱和限幅表。其余代码只见物理单位；`inv_vbus` 式魔法数禁止外泄。
3. **禁 `-ffast-math`，`-ffp-contract=off`**；三角函数以自研 sin 表为唯一实现（主机单测对 libm 只做容差比对）——保证主机回放与目标机一致。
4. **积分器状态存"未乘 ts 的和"，输出时再乘 ts**：`i_sum += err; out = kp*err + ki*ts*i_sum;`——根治积分停滞；dt 只出现在一个点（禁止"门控 500µs、dt 用 250µs"式隐藏 bug）。
5. **整数↔物理量换算只发生在 adapter/bsp 层**（ADC 计数→A 在 adapter，占空比→CCR 在 bsp），增益进板级配置。中间层永远只见物理量。

浮点三个阴招（写码时时刻警惕）：① double 静默提升（`1.0/3` 字面量、`sqrt` vs `sqrtf`）② 积分停滞（增量 < ulp 永远加不上去）③ NaN 传播且与任何数比较恒 false（**纯范围检查放行 NaN——比较恒假**，SET_SPEED 等入口必须补 isfinite）。

## 6. 资源与实时规范

### 6.1 R1 编码禁忌（RT 上下文 6 条）

1. RT（20kHz 管线）禁：malloc、printf、递归、无界循环、flash 写、LCD、SPI 长传输
2. 局部数组 >64 字节一律改 `static` 或入结构体（局部大数组是栈爆头号来源）
3. 缓冲/表的大小必须来自配置常量并过预算表（防 .bss 黑洞）
4. 大表（LUT/齿槽/字体）挂编译开关，不用即 0
5. 新函数进 RT 链前跑一次 ISR 耗时测量（DWT）
6. 链接脚本/栈/堆不擅自改，走 review

### 6.2 已定死的资源审核（不再讨论）

| 项 | 定值 | 备注 |
|---|---|---|
| 堆 | **0** | 无 malloc；禁 printf 家族 |
| 栈 | **8 KB** | 已落地（ld + startup）；水位实测后可回调 |
| RAM 预算 | 以《AxDr资源占用报告与预算.md》为准 | 资源曲线不允许单调上涨；`tools/build_measure.sh` 每步对比 |
| 大表开关 | AXDR_USE_LCD / USB / DIAG | 不用即 0 |
| NVIC 优先级 | RT 最高 → MID 次之 → 其余让路 | 全最高 = 无抢占控制 |

### 6.3 上板体检（每次硬件冒烟）

栈油漆水位 / DWT ISR 耗时 / CPU 负载——三项进 `debug_snapshot` 常驻字段。

## 7. 命令源与协议规范

1. **命令源平等**：USB、按键、旋钮地位完全平等，唯一路径是**只提请求 → 门面 API → 状态机/模式表校验**。
2. 任何命令源不得直写内部结构体字段、不得绕过门面调用控制层函数；请求被拒（状态不允许/参数越界）必须返回明确错误码并可查询。
3. 上位机新按钮 = 协议命令表注册一行（命令 ID → 门面调用），协议层只认识门面不认识内部结构。
4. **固件能力不存在时（如"导入参数包"）：先在门面加 API，再接按钮，顺序不可反。**
5. 命令表带版本号；上位机与固件协议版本不匹配必须显式报错。
6. 协议载荷变更原则：**只增不改不回退**；宿主解析按载荷长度兼容旧固件；新增字段放在结构体尾部。

## 8. 工程流程（本项目验收链）

### 8.1 提交格式

- 提交信息：**`<层/模块>: <中文一句话>`**（如 `service: 运行态补首故障定格`、`drive: 对齐增量更新`）。
- 算法 PR 必须附：host 单测结果 + 数值基准对比（可与录波对拍）。
- 验收通过后再 commit，不要未验证先提交。

### 8.2 验收门序列（不可跳）

1. **host 单测**（改固件逻辑必跑）：
   - `tools/run_host_tests.ps1` 受系统执行策略拦截，**不要用** `-ExecutionPolicy Bypass`；
   - 直跑方式：用本机 Qt 自带 MinGW gcc 手动编译对应测试，例：
     ```bash
     GCC="C:/Users/ready/Desktop/Axdr/AX_Driver_Lab/.tools/Qt/Tools/mingw1310_64/bin/gcc.exe"
     "$GCC" -std=c11 -Wall -Wextra -Wpedantic -Werror \
       -Itests/host/fakes -Ifirmware/AxDr_App/User/common \
       -Ifirmware/AxDr_App/User/control -Ifirmware/AxDr_App/User/algorithm \
       -Ifirmware/AxDr_App/User/motor -Ifirmware/AxDr_App/User/drive \
       tests/host/test_drive_state.c firmware/AxDr_App/User/drive/drive.c \
       firmware/AxDr_App/User/drive/drive_protection.c \
       -o build/test.exe -lm && build/test.exe
     ```
     （编译单元清单以 `run_host_tests.ps1` 内对应段为准）
2. **Keil 构建**：`bash tools/keil_build_check.sh` → 必须 **0 Error 0 Warning**。
3. **RAM 预算**：`tools/build_measure.sh`，资源曲线不允许单调上涨。
4. **真机冒烟**：烧 bin（axf 不能直接用 J-Link loadfile——RW 压缩尾不写入会 HardFault；用 `axf2bin.py` 从仓库根运行切 bin 再烧 `loadfile fw.bin,0x08000000`）。
5. commit。

### 8.3 决策流程

**动手前先调查、给选项、用户拍板**（项目铁律）：

1. 先调查参考项目/既有代码的真实惯例，**核实出处**；
2. 整理 2~4 个**带证据**的选项交给用户选择；
3. 用户拍板后实施；结论记入相关文档。

禁止自作主张改协议号段、改架构、批量重命名。
