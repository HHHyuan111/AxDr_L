# 01 开发约束细则（无 AI 痕迹执行标准）

> 本文件是《00_开发总规范》的执行细则，把"无 AI 痕迹、模块清晰、对仗工整"这些
> 抽象要求变成可逐条机械检查的具体规则。所有条款默认【强制】。
> 与 00 总规范冲突时以 00 总规范为准；本文件只做细化，不新增与之矛盾的条款。
> 文件名可改，条款编号在开发中被引用，勿随意重排。

---

## 0. 总判据

任何一段代码交付前，必须能通过"人味检查"：一位有经验的嵌入式工程师逐行读下来，
不会产生"这不像是人手写的"的感觉。判断不靠感觉，靠下面五章的机械检查——
检查过不了，就必须改到能过。

适用对象：**现在和以后的全部代码**（存量代码在整理阶段逐块改造，新代码直接按本细则写）。

---

## 1. 结构：主链一条直线

### 1.1 七步主链固定
`control_cycle_step` 内只出现编号 1~7 的步骤注释和对应调用，编号不增不减、顺序不变。
测速、观测、快照、周期记录等支线只允许在主链之前或之后，**不得插入两步之间**。

```c
/* 1. 读取反馈：采样、有效性、速度和母线限幅。 */
foc_read_feedback(foc, input);
/* 2. 检查保护：电流、电压、编码器有效性和启动方向。 */
drive_check_protection(foc);
/* ... 3~7 依次类推，句式一致 */
```

### 1.2 单函数单职责
一个函数不得同时承担下列两类及以上：状态判断 / 执行动作 / 提交硬件 / 协议映射。
现有 `drive_output` 的"提交 + 诊断校验 + 停机 + 协议映射"混装属于违例，整理阶段必须拆开。

### 1.3 禁止纯转发
函数体只有一行调用且不改变任何语义 = 纯转发，删除或并入调用方。
"为解耦而解耦"的包装层一律不建；新边界必须能说出实际需要（换硬件 / 换算法 / 换命令源）。

### 1.4 调用链每跳可解释
主链每跳都能用一句话说明职责（"这一跳负责把采样换算成 SI 单位"）。
说不出的跳数，删除。

### 1.5 文件内顺序固定
公开入口函数在前、按主流程顺序排列；static 辅助函数在后。
头文件顺序：类型定义 → 公开函数声明。

## 2. 格式：对仗工整

### 2.1 步骤/列表类注释句式统一
动宾短语，长度相近（"读取反馈 / 检查保护 / 更新状态"）。同一列表内不混长句和短句。

### 2.2 switch 分支形状一致
每个 case 的注释位置、break/return 方式统一；`default` 必须存在；分支间空行规则一致。

### 2.3 结构体字面量字段按声明顺序写
禁止打乱顺序的指定初始化；每个模块只保留一种初始化模板。

### 2.4 include 分四组，组间空行
本模块头 → 标准库 → 项目公共头 → 本层/下层头。不按字母序硬排，按依赖关系。

### 2.5 连续赋值对齐 `=`
相关字段成组，组间一个空行，组内对齐。

### 2.6 同一文件注释风格二选一
行尾注释统一 `/* ... */` 或 `// ...`，一个文件内不混用。

### 2.7 继承 00 规范 §3.1
4 空格缩进、禁 Tab、行宽 ≤120、if/for/while 单句也加花括号、文件以换行结束。

## 3. 注释：只讲为什么，禁止废话

### 3.1 代码注释黑名单（出现即改）
| 黑名单句式 | 处理 |
|---|---|
| "是 A，不是 B" 对比式否定 | 只保留 A 的正面表述，删掉 B |
| "不负责 X""不会 Y""并不能 Z" 职责澄清式 | 删（职责由文件头和函数位置体现） |
| "需要说明的是""值得注意的是""需要注意的是" | 删，直接说内容 |
| "具体来说""换句话说""综上所述" | 删 |
| 四段式空泛 @param 模板（无新增信息的参数复述） | 精简为一句话目的 |
| 注释复述代码字面行为（"先赋 a，再赋 b"） | 删 |

**例外**："避免/防止 + 原因"属于解释动机，保留。
例：`/* 启动前先写 50% 中性占空比，避免沿用旧比较值。 */`

### 3.2 只写为什么
注释解释动机、边界、易错点。代码做了什么，读代码就知道，不注释。

### 3.3 函数头 ≤3 行
目的 + 单位 + 前置条件/副作用；没有就不写，不凑模板。

### 3.4 字段搬运、初值赋值不加注释

### 3.5 错别字零容忍；注释中文、标识符英文（00 规范 §3.7）

### 3.6 正反例对照（来自本仓库真实代码）

| 反例（AI 味） | 正例（人味） |
|---|---|
| `/* 对齐是校准动作，不是运行授权。立即关闭 PWM，避免对齐命令与此前缓存的速度/电流目标在同一个状态链中自动接通。 */` | `/* 对齐只是校准；完成后必须再次 START 才能运行。 */` |
| `本函数不访问 HAL、Target 或全局电机对象，不分配内存，也不阻塞` | `纯算法，可在主机上单独测试` |
| `/* 返回本拍最终状态与占空比，供调用方或离线测试读取。 */`（函数体就是赋值，读得出来） | 删 |
| `/* 0.001f 等于 1/1000，把累加值换算成 1000 次采样的平均值。 */` | `/* 1000 次采样的平均值。 */` |

## 4. 命名：短而有据

### 4.1 公开函数 = `模块_动作`，小写 snake_case
static 内部函数可不带模块前缀，但语义必须完整。

### 4.2 沿用短名惯例，单位写进类型头注释
项目已有惯例：`fb`（反馈）、`ref`（给定）、`cmd`（命令）、`out`（输出）、`spd`、`pos`、
`cur`、`enc`、`ia/ib/ic/id/iq`、`theta_e`、`vbus`。新短名必须与旧语义一致；
单位不写进字段名，统一写在类型定义头部（如 `foc_fb_state_t` 头部声明"电流 A、角度 rad"）。

### 4.3 禁止
- 长到自解释的组合名（`drive_cycle_command_is_valid_and_ready` 式）；
- 无信息量泛词：`flag`、`data`、`info`、`para`、`temp`；
- 为对称而对称的命名（两个功能不同的东西起一对结构相同的名字）。

### 4.4 枚举值和宏大写 + 类型前缀（00 规范 §3.2）

## 5. 节奏：有轻重

### 5.1 函数长短自然
3 行 getter 与 40 行核心算法并存是正常的；不追求每个函数差不多长。

### 5.2 防御检查每处可解释
每处新增检查必须能一句话回答：谁、在什么条件下触发、后果是什么。
答不出的检查删掉。

### 5.3 错误处理一层就够
外层已保证的不在里层重复防御；快环内的错误路径直白（一个 if + 返回），不叠三层。

### 5.4 不堆"通用防御"
禁止为了"万一"而加的检查；每个分支都要对应一个真实存在过的或能推导出的场景。

## 6. 复用参考工程

### 6.1 写新模块前先查参考
四个参考工程（路径见 §9）里有同类模块的，先读；不重复发明。

### 6.2 三档复用判定
| 档 | 条件 | 做法 |
|---|---|---|
| 直接移植 | 结构、注释风格都符合本细则和 00 规范 | 整体搬入，改模块前缀和单位表述 |
| 搬算法重写外壳 | 算法好、风格不符 | 只搬数值部分，按本细则重写接口和注释 |
| 只借鉴组织方式 | 算法不符合本项目 | 借鉴分层/排版/分段，不搬代码 |

### 6.3 复用必须带来源注释
`/* 参考 <工程名> <文件名>：<一句话说明借了什么> */`

### 6.4 移植纪律
GBK 文件先转 UTF-8 再读；不照搬上电自动辨识/自动进入运行的行为（本项目保留显式启动授权，见 00 规范与交接文档）。

## 7. 工作流程与验收

1. **提交由负责人执行**：我完成改动和自检后交付，由负责人验证、上传 git；我不自行 commit/push。
2. **第一阶段只修基线**：解决当前编译不一致问题，不做风格清理；负责人验证通过后冻结，再开始后续开发。
3. **每阶段动 ≤1 个职责边界**（00 规范 §9）；先给方案、负责人拍板、再动手。
4. **文档体系后置**：代码全部改完后，在现有文档基础上重建一套干净文档。
5. 验收门继承 00 规范 §8.2，顺序不可跳。

## 7.5 环境与工具坑位（已发生过的实坑，避免重犯）

| 坑 | 现象 | 处置 |
|---|---|---|
| Keil 编辑器缓冲 | 文件在 Keil 打开时被外部修改，Rebuild 会把旧缓冲**保存回磁盘**覆盖新文件，报错内容是"旧代码" | 改文件前先关 Keil 或 Reload；构建报旧代码错误时先查磁盘文件哈希再判断 |
| 烧录 axf | J-Link 直接 loadfile axf → RW 压缩尾不写入 → HardFault | 只烧 bin：`loadfile AxDr.bin,0x08000000` |
| git 代理过期 | 配置的 127.0.0.1:7897 不在监听，push 连接失败 | 查 netstat 找当前代理端口，`git -c http.proxy=... push` 一次性覆盖，不改全局配置 |
| .ps1 执行策略 | run_host_tests.ps1 被系统策略拦 | 不 -ExecutionPolicy Bypass；用 Qt MinGW gcc 手动编译（复刻脚本见 artifacts） |
| ps1 两处过期 | 引用 `legacy_cascade.c`（实为 `legacy_control_cascade.c`）、control_loop 块缺 `-Wno-misleading-indentation` | 已记录备案，负责人批准前不顺手修 |

## 8. 每轮交付自检清单（机械执行，结果随交付汇报）

| 编号 | 检查 | 方法 |
|---|---|---|
| S1 | 注释黑名单 | grep 扫描本次改动："不是\|不能\|不负责\|并不会\|需要说明\|值得注意的是\|换句话说"，逐条改写或删除，过不了的列清单说明理由 |
| S2 | 七步主链 | `control_cycle_step` 编号 1~7 各一次、顺序不变、支线未插队 |
| S3 | 纯转发函数 | 本次改动中函数体一行且只调一个函数的，列出并说明去向 |
| S4 | 函数头长度 | 本次改动中函数头 >3 行的，列出并精简 |
| S5 | 命名 | 新增公开函数带模块前缀；无 flag/data/info 泛词；新短名与惯例一致 |
| S6 | 防御检查 | 新增的每处检查逐条写出触发场景与后果 |
| S7 | 构建门槛 | host 单测绿；涉及固件时 Keil 0E0W |
| S8 | 汇报 | 回复中附自检结果：每项过了什么、未过的列清单与理由 |
