# 02 架构决策与状态机规范

> 定位：把已讨论拍板的架构决策固化为强制规则。开发中**不再重新讨论**本文件已定事项；
> 要改变其中任何一条，必须提出新证据并重新拍板。
> 优先级：与 00 总规范冲突以 00 为准；与 01 细则冲突以 01 为准；本文件只记录决策，不改规则本身。

---

## 1. 一拍主链（七步，顺序固定）

`control_cycle_step` 是唯一一拍入口，硬件路径与离线显式输入共用。

| 步 | 名称 | 输入 | 输出 | 写者 |
|---|---|---|---|---|
| 1 | 读取反馈 | 采样/离线输入、有效性 | fb 各物理量 + 测速 | app + adapter |
| 2 | 检查保护 | 本拍反馈 | fault 锁存位、首故障定格 | drive |
| 3 | 更新运行状态 | req、fault、当前 state | 新 state + 进入动作 | drive |
| 4 | 处理状态并生成给定 | state、mode | `foc_plan_t`（给定 + 本拍控制角 theta） | drive/motor |
| 5 | 更新电流与角度 | ia/ib/ic、theta | Clarke/Park → id/iq | motor |
| 6 | 执行控制 | id/iq、给定、母线 | 三相占空比候选 | control |
| 7 | 输出 PWM | 占空比、状态、fault | 校验后写比较寄存器或关断 | drive |

规则：
- 第 5、6 步只在**本拍有给定且无锁存故障**时执行；
- 支线（观测、只读快照、周期记录）只允许在主链**之后**，测速在第 1 步内；
- 七步编号注释 1~7 各一次、不插队（01 细则 §1.1）；
- 每跳必须能用一句话说出职责（01 细则 §1.4）。

## 2. 状态机规范（借鉴 iFOC，落为静态 C 分支）

### 2.1 三分法（三个概念，分别表达，不许混）

| 概念 | 存放 | 含义 | 谁写 |
|---|---|---|---|
| `foc->req` | 外部请求 | STOP / START / RUN，命令源和服务层可写 | 门面/服务层 |
| `foc->state` | 持久运行状态 | 当前是否允许输出、处于哪个阶段 | drive 层唯一写者 |
| `foc->mode` | 控制模式 | 允许输出时**怎么算**（VF/IF/电流/速度/位置/MIT/诊断） | 命令源经门面发布 |

### 2.2 状态表

| 状态 | 进入动作 | 持续动作 | 退出条件 |
|---|---|---|---|
| STOP | 关 PWM（若在活动）、清控制器历史、对齐进度作废 | 无 | 收到 START 且保护/模式允许 |
| STARTING | 写 50% 中性占空比 → 开 PWM → 清控制器 → 置 req=RUN | 本拍只启动 | 下一拍进入 RUN / DIAG（ABZ 未对齐先进 ALIGN） |
| ALIGN | 对齐进度清零开始 | 1s 渐变 → 1.5s 扫场 → 0.7s 保持（见 §9） | 成功→自动停机回 STOP；失败→enc_err 回 FAULT |
| RUN | 无（已运行） | 按 mode 生成给定 | STOP 请求 / 故障 / 模式不可执行 |
| DIAG | 诊断授权检查 | 运行诊断并检查诊断电压边界 | STOP / 故障 / 诊断结束 |
| FAULT | 关断、锁存 | 保持锁存 | 显式清除（DISARM / drive_fault_clear） |

### 2.3 状态机规则（强制）

1. 进入动作集中在 `drive_enter_state`，持续运行**不重复**启动、清 PI、重置对齐进度；
2. 重复 START 不重新初始化（已在运行就保持）；
3. RUN ↔ DIAG 之间必须经过 STOP 和重新授权；
4. 对齐完成**不自动进入 RUN**——自动停机，必须再次显式 START（校准≠运行授权）；
5. 故障锁存后必须显式清除才允许再启动；
6. 关断失败保留 pwm_active 和 FAULT，**不得报告已安全停机**；
7. 协议兼容映射（原 STOP=0/STARTING=1/RUN=2/FAULT=3 四状态）只允许在 service 层做；
8. iFOC 只借鉴"持久当前状态 + 请求 + 一次性进入动作"三件逻辑；C++/RTOS/任务注册机制不搬；
9. `drive_cycle_t` 只保存本拍给定与计算结果（cmd/ready/valid），**不保存运行状态**。

## 3. 控制角度 theta 的语义与来源选择

- `theta` = 本拍控制用场角，由第 4 步按状态/模式选好，第 5 步只用不选；
- 来源规则：

| 情形 | theta 来源 |
|---|---|
| 有感闭环（电流/速度/位置/MIT） | 编码器电角（要求已对齐） |
| VF / IF | 虚拟积分场角（与编码器无关） |
| 对齐 | 校准场角（扫场序列） |
| 无感（预留） | 观测估计角（未锁定不得被选作控制反馈） |

- VF/IF **不要求**编码器对齐，不允许进入 ABZ 对齐流程；
- 位置闭环不得把开环积分角当实测位置；
- 角度/速度及其有效性**独立保存**（编码器实测、虚拟积分、观测估计各是各的），选择哪个用于控制由第 4 步显式决定。

## 4. 反馈数据流与唯一写者

### 4.1 各层只做自己的事

| 层 | 职责 | 不负责 |
|---|---|---|
| BSP | 提供原始量（ADC 计数、编码器计数、PWM 写比较寄存器） | 物理量换算、有效性组装 |
| Adapter | 原始量 → SI 物理量（A/V/rad/rad/s） | 状态判断、模式选择 |
| app | 组装本拍 feedback、测速、装入 foc->fb | PI、寄存器操作 |
| drive | 保护判断、状态转换、PWM 提交裁决 | Clarke/Park、PI 公式 |
| motor | 派生量（转矩/滤波速度等）、foc_t ↔ 可移植控制器映射 | 运行状态调度 |
| control | 坐标变换、PI、限幅、调制 | HAL、全局电机对象 |

（回应交接文档疑问：反馈组装不在 BSP——BSP 只提供原始量，组装与有效性属于运行时编排；
不与 FOC 核心放一起——FOC 核心是纯算法，反馈组装依赖本工程的数据模型。）

### 4.2 唯一写者表（新增字段必须登记）

| 字段族 | 唯一写者 | 上下文 |
|---|---|---|
| foc->fb 物理量与有效性 | control_cycle_step（经 adapter 换算） | RT |
| foc->state / req 的运行部分 | drive 层 | RT |
| foc->req 的请求部分 | 服务层（临界区内） | MAIN |
| foc->ref / mode / cmd | 服务层经门面（临界区内整组发布） | MAIN |
| foc->fault | 保护/对齐/守卫各方置位，仅 fault_clear 清除 | RT/MAIN |
| pwm_cmd / pwm_commit | drive_output / drive_pwm_commit | RT |
| 其余算法状态 | 各算法对象（结构体内） | 按其 tick 上下文 |

规则：采样失败**保留上拍数值但有效性置 false**，由保护决定后续；不静默沿用无效数据当有效。

## 5. PWM 提交规范（唯一关口）

1. 普通占空比**只有** `drive_output → drive_pwm_commit` 一个提交口；
2. 校验顺序固定：有限值 → 0~1 范围 → 相序映射 → Target 写比较寄存器；
3. 启动前必须**先写 50% 中性占空比再开输出**（防止沿用旧比较值）；
4. `pwm_cmd.valid` 每拍清零；无有效计算、相序非法、故障时**关断，不沿用上一拍**；
5. 停止路径与故障路径复用同一关断动作；关断失败 → pwm_err + 保持 FAULT。

## 6. 保护规范

1. 检测方只**置位**故障位；Drive 统一执行停机处置；
2. 首故障定格：fault 从 0→非 0 的首拍锁存位图与 fast_seq，DISARM 时一并清除；
3. 故障清除 = 显式动作（DISARM / drive_fault_clear），清除前不得重启；
4. 保护前提**按模式定义**（S2 阶段落地）：有感闭环要求有效标定；VF/IF 不要求编码器；
5. 未接入的采样（温度 ADC）不得宣称有效，对应保护不得列为已完整接入；
6. 启动方向守卫只用于发现编码器方向/相序明显反向，不改变正常换向语义。

## 7. 命令发布规范

1. 命令源平等（USB/按键/旋钮），唯一路径：请求 → 门面 API → 状态机/模式表校验；
2. 服务层经**短临界区**整组发布命令；快环只能看到整组旧命令或整组新命令；
3. STOP 永远优先；STOP 后旧运动命令不得重新启动；
4. 命令租约超时 → fail-closed（撤销授权 + 停机），stop_reason 按契约填写；
5. 协议载荷**只增不改不回退**，宿主按载荷长度兼容旧固件，新字段放尾部；
6. 协议 opcode 号段已占用：0x13/0x16（辨识）、0x1B~0x1F（扫频）、0x30~0x36（被动观测）——新协议先查能力位与号段，不重复造轮子；
7. 上位机新按钮 = 协议命令表注册一行；固件能力不存在时先加门面 API 再接按钮。

## 8. 测速规范

1. N 拍差分需要 **N+1** 个连续有效样本；样本不足不得置就绪；
2. 用周期序号判连续性（无符号差，回绕安全）；序号不连续或样本无效 → 重建窗口，期间**保持上次速度**，不用压缩时间算速度；
3. 测速状态在每个电机对象里（禁文件级 static），多实例不串状态；
4. 窗口内转角须 < π（单圈解卷绕）；跨圈、重初始化均有测试。

## 9. 编码器对齐规范（ABZ 上电定零）

1. 序列：1.0s 电流线性渐变 → 1.5s 扫场一整圈（0→2π 收尾到 0）→ 0.7s 保持，末 0.3s 圆均值采样；
2. 定零语义 = 吸合停位即零位：`e_off −= 圆均值（mod 2π）`，**不清编码器计数器**，重对齐不叠加；
3. 成功：`enc_aligned = true` → 立即停机 → 等显式 START；
4. 失败（圆均值集中度 < 0.9）：置 enc_err、清进度，清故障后重新 START 可重试；
5. 扫场参数沿用既有台架验证值；圆均值只检查样本集中度，不独立证明跟场到位。

## 11. 参考工程借鉴边界（每工程借什么、不借什么）

| 工程 | 借鉴 | 不搬 |
|---|---|---|
| iFOC | 持久当前状态、RequestState、一次性进入动作 | C++/RTOS/任务注册机制 |
| G11 | foc_run 的反馈→保护→状态→控制→输出顺序、核心与硬件适配边界 | READY/退流语义（本项目 STOP=关 PWM） |
| HS_MOTOR | 围绕 RunState 的直白 switch、排版分段、教学注释方式 | 上电自动辨识、自动进入运行 |
| USST | 采样、状态、三闭环的组织方式（先定位真实用户控制入口） | 未核实的入口文件一律不算借鉴依据 |
