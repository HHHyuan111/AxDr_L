# 底层确定性问题修复

日期：2026-08-27

## 1. 节点目标和边界

本节点只处理含义明确的底层未定义行为和基础接口错误，不调整控制公式，不批量重命名，不拆分结构体，也不清理未使用变量等一般警告。

## 2. 修改内容

1. 主循环计时变量在第一次参与差值计算前，使用当前系统 Tick 初始化。
2. 三相电流零偏的三个累加器从 `0.0f` 开始，避免用随机栈数据计算 ADC 偏置。
3. MT6825 接收缓冲区明确清零；两个尚未实现的 DM485 编码器桩函数明确返回 0，不再从非 `void` 函数直接退出。
4. GPIO 端口参数按枚举范围和实际端口表检查，不再把枚举值与空指针比较。
5. GPIO 读取函数返回 HAL 的真实引脚状态，不再丢弃读取结果并固定返回 0。
6. 当前工程只存在 UART3 和 FDCAN1 句柄；UART1/2、FDCAN2/3 不再伪装成可用端口。
7. UART/FDCAN 操作默认返回失败，只有端口有效并实际调用 HAL 后才用 HAL 结果覆盖。

## 4. 有意保留的问题

`eh_observer.c` 仍有 `u1` 和 `x3` 两个未初始化读取警告。

- `u1` 在赋值前参与观测误差计算，无法确认它表示本周期还是上周期状态。
- `x3 +=` 表明它可能是跨控制周期的积分状态，但当前被声明为局部变量。
- 直接给二者补零会改变观察器公式，不能把“警告消失”冒充“算法正确”。

因此本节点没有修改观察器。恢复它之前需要先确认原始公式、状态归属和复位条件；当前仍不具备硬件运行验收条件。

## 5. 节点结论

可以从现有代码语义直接确定的底层问题已经修复，Debug 和 Release 均保持可构建。下一节点开始前，先向用户讲清这些修改及观察器为什么不能直接补零。
