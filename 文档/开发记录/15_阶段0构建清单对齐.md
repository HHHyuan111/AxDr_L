# 开发记录 15：阶段 0 构建清单对齐

## 1. 本节点要解决什么

项目同时保留 CMake/GCC 和 Keil 两套工程，但启动 Goal 时两边的 User C 源文件清单不同：
CMake 编译 30 个，Keil 只登记 22 个。

本节点只把两套工程的源文件入口对齐，确保后续重构不会出现“一个工程能编，另一个工程漏文件”的情况。
没有修改任何 C/H 源码，没有调整 FOC 公式、参数、状态机、ADC/PWM 时序或默认运行模式。

## 3. 本节点修改内容

### 3.1 Keil 工程补齐 User/bsp 组

在 `AxDr.uvprojx` 中新增 `User/bsp` 分组，并登记以下 8 个已经存在于 CMake 活动清单中的源文件：

- `bsp_cpu.c`
- `bsp_fdcan.c`
- `bsp_flash.c`
- `bsp_gpio.c`
- `bsp_uart.c`
- `target_adc.c`
- `target_encoder.c`
- `target_pwm.c`

对齐方向以当前可重复构建的 CMake/GCC 基线为准。该基线从项目最初版本起就编译全部 `User/bsp/*.c`；
如果反过来从 CMake 删除 5 个原有 BSP 文件，会改变当前 GCC 固件的链接内容，不符合本节点“不改现有行为”的边界。

Keil 原有头文件路径已经包含 `User/bsp/inc` 和 `User/bsp`，因此没有改 IncludePath。

`User/moldue/w25q16.c` 在两套工程中原本都没有启用，本节点继续保持不启用。

### 3.2 增加最小清单检查脚本

新增 `tools/check_user_source_parity.ps1`。脚本只比较两套工程中活动的 `User/*.c` 路径，
不比较 CubeMX、HAL、CMSIS 和启动文件。检查通过时退出码为 0，发现差异时列出差异并返回失败。

运行方法：

```powershell
.\tools\check_user_source_parity.ps1
```

当前结果：

```text
CMake 用户源文件：30 个
Keil 用户源文件：30 个
检查通过：CMake 与 Keil 的 User C 源文件清单一致。
```
