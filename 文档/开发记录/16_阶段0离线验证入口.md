# 开发记录 16：阶段 0 离线验证入口

## 1. 本节点要解决什么

后续重构会逐步拆分 FOC、状态机和硬件适配层。为了避免“代码看起来更整齐，但结果悄悄变了”，
本节点先建立两个最小验证入口：

1. 固件每次都做 Debug/Release `clean-first` 非增量重建，并阻止警告数量超过当前基线。
2. 在电脑端直接编译现有 FOC 数学源码，保存最基础的数值行为。

本节点没有修改任何生产 `.c/.h` 文件，也没有改变中断、状态机、PWM 或控制参数。

## 2. 固件构建门禁

新增 `tools/check_firmware_build.ps1`。脚本固定完成以下事情：

- Debug 执行 `--clean-first` 非增量重建；
- Release 执行 `--clean-first` 非增量重建；
- 任一构建退出码非 0 时失败；
- 任一配置警告超过 104 条时失败。

当前 104 条是 Arm GNU Toolchain 16.1.0 下的既有基线，其中包含链接器的 RWX 段警告。
脚本的目的只是防止重构时明显增加警告，不把旧代码一次性清零，也不代替静态分析和代码评审。

运行结果：

```text
Debug 构建通过：0 个错误，104 个警告，基线不超过 104 个。
Release 构建通过：0 个错误，104 个警告，基线不超过 104 个。
```

## 3. 电脑端 FOC 数学测试

新增 `tools/run_host_tests.ps1` 和 `tests/host`。测试使用电脑端 GCC 16.2.0，直接编译：

- 生产源码 `User/motor/foc_calc.c`；
- 生产源码 `User/motor/util.c`；
- 测试源码 `tests/host/test_foc_math.c`。

测试没有复制 FOC 公式。`fakes/main.h` 只提供 CMSIS 的 `__IO`、`__I` 类型限定符，
`fakes/bsp.h` 是空的硬件边界，因此测试调用的仍然是当前生产算法。

首批测试刻意保持很小：

- 一组平衡三相电流的 Clarke 变换；
- 零角度下的 Park 变换；
- 逆 Park 与逆 Clarke 的固定数值；
- SVM 零矢量和一个非零矢量的固定三相占空比；
- `foc_calc()` 从电流和角度输入到 dq 电流、三相占空比的一个端到端向量。

运行结果：

```text
Host C11/FOC 数学测试通过。
```

这些测试只证明当前数值结果，不证明 Cortex-M4F 执行时间、ADC/PWM 同步或真实硬件行为。
更多扇区、边界值、PI 和速度/位置环测试留到对应算法迁移节点，不在这里一次铺满。

## 4. 当前快速路径的链接基线

Debug 和 Release ELF 中均确认存在以下快速路径关键符号：

```text
HAL_ADCEx_InjectedConvCpltCallback
axdr_app_fast_step
target_adc_read_raw
target_encoder_read_mt6816_raw
encoder_sample
position_update
foc_adc_sample
foc_feedback_update
pmsm_run_state_machine
pmsm_run_selected_mode
foc_curr
foc_pwm_run
target_pwm_set_duty_ratios
```

需要准确理解当前链接结果：链接脚本把输入 `.RamFunc` 合并到了 ELF 输出 `.data`，
所以这些函数在 ELF 中显示为位于 RAM 地址的 `.data`，并不存在独立输出 `.RamFunc` 段。
现有 `.fast_ram` 是另一个 128 B 段，当前放置 `eh_vobs`、`eh_tobs`，不能和 `.RamFunc` 混为一谈。

ADC 应用回调虽然位于 RAM 侧，链接器仍在 Flash 中生成了跳转 veneer。因此这里只记录符号和段归属，
不宣称“整条中断链全部在 RAM”，也不宣称实时周期已经通过硬件验证。
