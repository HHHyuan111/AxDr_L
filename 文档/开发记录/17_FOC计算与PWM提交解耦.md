# FOC 计算与 PWM 提交解耦

## 本节点要解决什么

旧代码在 `foc_volt()`、`foc_curr()`、`foc_vel()`、`foc_pos()` 内部既计算控制量，又直接写入 PWM。这样一来，控制算法和硬件输出绑在了一起：以后做离线回放、仿真或 HIL 时，只想计算占空比也会碰到硬件写入。

本节点只拆开这两个职责，不改控制公式、参数、状态机和硬件执行顺序。

## 改完后的大白话流程

```text
运行模式或标定流程
    ↓
调用 FOC，计算 dtc_a、dtc_b、dtc_c
    ↓
FOC 返回“本次占空比是否有效”
    ↓ 有效
调用 foc_pwm_commit()
    ↓
按照 ABC/ACB 相序排列三相占空比
    ↓
Target 层写入 TIM1 的三路 PWM
```

四个 FOC 函数现在返回 `bool`：

- `true`：SVM 计算成功，`dtc_a/b/c` 可以提交；
- `false`：SVM 计算失败，本周期保持原来的 PWM，不写新值。

`foc_pwm_commit()` 只做两件事：根据相序排列三相占空比，然后调用 Target 层。它不再承担控制算法计算。

## 为什么没有统一放到中断末尾再写 PWM

编码器标定会先计算并写入本周期 PWM，随后才可能修改 `phase_order`。如果统一拖到中断末尾提交，就可能提前一个周期使用新相序。

另外，标定路径在原 PWM 写入点后还存在较大的循环计算。把提交移到这些计算之后，可能错过当前 PWM 更新窗口。因此本节点采用最小迁移方式：FOC 返回后，调用者仍在原位置立即提交，保持现有实时先后关系。

## 明确保留的旧行为

- `start` 仍然按照“启动三相输出 → 写 50% 占空比 → 复位控制器”的原顺序执行；
- `reset`、未实现模式和 SVM 失败时不提交新的运行占空比；
- 快速停车、故障减速、编码器标定、参数辨识和齿槽标定仍在原计算点立即提交；
- ABC/ACB 映射规则不变；
- FOC 数学公式、PI 参数、采样顺序和状态机行为均未修改；
- TIM1 通道 4 仍是 ADC 触发链的一部分，不属于三相占空比提交接口。

## 修改范围

- `common.h`：四个 FOC 接口改为返回 `bool`，`foc_pwm_run()` 改名为 `foc_pwm_commit()`；
- `foc_drv.c`：FOC 只计算并返回结果，不再直接写硬件；
- `foc_ctrl.c`：各运行模式在 FOC 返回有效后立即提交；
- `calibration.c`、`anticogging.c`、`idpm.c`：标定和辨识路径在原位置立即提交。

本节点没有增加输出结构体、全局有效标志、事件总线、限幅或额外防御逻辑。

## 离线验收结果

- CMake 与 Keil 用户源清单一致：30 / 30；
- Debug clean-first 构建：0 错误，104 个既有警告，无警告增量；
- Release clean-first 构建：0 错误，104 个既有警告，无警告增量；
- Host C11 / FOC 数学回归：通过；
- `foc_pwm_run` 旧符号：0 处；
- 运行期三相 CCR1～CCR3 的直接写入仍集中在 Target 层。

## 尚未做的硬件验证

本节点没有烧录和带电测试。后续上板时需要用示波器、逻辑分析仪或 DWT/GPIO 标记确认：ADC 快速回调到 CCR 更新的最坏耗时没有跨过 TIM1 的目标更新事件。
