# 阶段 1 架构导读与验收

## 一句话说明现在的框架

快速中断只负责叫醒统一入口；应用层按固定顺序更新角度、采样和反馈；状态机决定本周期做启动、复位还是运行；FOC 只计算三相占空比；调用者确认计算有效后，立即经由 Target 层写入 PWM。

## 当前一次快速周期怎样运行

```text
ADC1 注入转换完成
    ↓
HAL_ADCEx_InjectedConvCpltCallback()
    ↓
axdr_app_fast_step()
    ├─ 1. encoder_sample()       取得编码器原始值
    ├─ 2. position_update()      计算机械角和电角度
    ├─ 3. foc_adc_sample()       经 Target 取得 ADC，并换算三相电流
    ├─ 4. foc_feedback_update()  更新母线电压、转矩、速度和观测量
    └─ 5. pmsm_run_state_machine()
            ├─ pmsm_exec_action()  执行 start / reset / opera
            ├─ 运行模式调用 FOC
            │      └─ 只计算 dtc_a / dtc_b / dtc_c
            ├─ 计算成功后立即 foc_pwm_commit()
            │      └─ Target 写 TIM1 CCR1 / CCR2 / CCR3
            └─ pmsm_eval_state()  更新结果状态并处理故障优先级
```

这张图表达的是职责和调用先后，不表示每一步都已经迁入独立文件夹。当前 Drive 状态与模式编排仍主要位于 `foc_ctrl.c`，后续会在行为明确后再做物理目录迁移。

## 每一层现在管什么

| 逻辑职责 | 当前主要位置 | 负责内容 | 不负责内容 |
|---|---|---|---|
| Fast App | `User/app/axdr_app.c` | 快速周期顺序和初始化门控 | 不展开控制公式，不直接写 PWM |
| Target | `User/bsp/target_adc.c`、`target_encoder.c`、`target_pwm.c` | 读硬件结果、启停输出、写比较寄存器 | 不决定运行模式，不计算 FOC |
| Drive 编排 | `User/motor/foc_ctrl.c` | 执行控制请求、选择模式、更新运行状态 | 不把状态判断塞进 FOC 数学函数 |
| Control / FOC | `User/motor/foc_drv.c`、`foc_calc.c` | 坐标变换、PI、SVM，生成 `dtc_a/b/c` | 计算函数不直接写硬件 |
| 标定与辨识 | `calibration.c`、`anticogging.c`、`idpm.c` | 生成实验目标并调用 FOC | 不绕过统一 PWM 提交接口 |

## 本阶段真正完成了什么

### 1. FOC 计算与硬件提交分开

`foc_volt()`、`foc_curr()`、`foc_vel()`、`foc_pos()` 现在返回 `bool`：

- 返回 `true`：本次 SVM 结果有效，调用者提交 `dtc_a/b/c`；
- 返回 `false`：本周期不更新 PWM。

20 个生产调用点都按这个返回值处理，并且仍在原来的位置立即提交。没有新增全局标志、输出大结构或事件总线。

### 2. PWM 提交只有一个清楚的入口

`foc_pwm_commit()` 负责把逻辑 A/B/C 相占空比按 ABC 或 ACB 接线映射到三个物理通道，再调用 Target。

TIM1 的 CCR1、CCR2、CCR3 仍只有 `target_pwm.c` 直接写。START 使用的三路 50% 设置也仍经过同一个 Target 接口。

### 3. 状态机的动作和结果判断分开

- `pmsm_exec_action()`：只做启动、停止或运行；
- `pmsm_eval_state()`：只判断结果状态；
- `pmsm_run_state_machine()`：保存入口请求，按顺序调用两者，再执行故障最终规则。

状态名、枚举数值、启动顺序、停止顺序和模式映射都没有改变。

## 本阶段故意没有改变什么

以下内容属于行为修改，阶段 1 没有顺手处理：

- 默认初始化仍把 `ctrl_bit` 设为 `start`；
- 源码内部仍没有自动把 `start` 切换到 `opera`，通常需要调试器或后续通信逻辑修改请求；
- START 仍按“启动输出 → 写 50% → 清控制器”的旧顺序执行；
- `main.c` 中原有的三相输出启动时机没有调整；
- 角度采样和电流采样的先后问题仍按用户要求暂时保留；
- 没有重命名整棵旧代码、重整参数、修改 PI/SVM 公式或加入复杂保护框架；
- 没有把 PWM 提交拖到整个中断末尾，因为标定路径可能在 FOC 后修改相序并执行较大循环。

这些事项要先明确期望行为和硬件验收方法，得到确认后才能进入下一阶段。

## 尚未完成的硬件验收

本阶段没有烧录、带电和电机运行测试，因此以下结论尚不能用离线构建替代：

- ADC 回调到 CCR 更新的最坏执行时间；
- Debug 状态机新增函数边界带来的调用栈和执行时间；
- PWM 更新是否稳定落在预期 TIM1 更新窗口；
- ABC/ACB 实际接线方向与编码器方向；
- START、RESET、FAULT 在 Gate 和三相波形上的真实先后；
- 电流、速度、位置和 MIT 模式的实机动态表现。
