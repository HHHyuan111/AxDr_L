# 只读调试快照

## 一句话说明这一步

在每个快速控制周期结束时，把本周期最终的状态、反馈、目标和 FOC 结果复制到独立的 `g_debug_snapshot`，让调试器直接观察，不再要求调试代码深入读写整个 `pm`。

这里的“只读”指数据方向只有 `pm -> 快照`。快照本身必须由发布函数写入，所以 C 类型不能声明成 `const`；但 Drive、Control 和控制流程都不会读取它，调试器即使改了快照字段，也不会反向改变电机控制。

## 它放在快速周期的哪里

```text
更新编码器和角度
    ↓
更新 ADC 和三相电流
    ↓
更新母线、电流、转矩、速度反馈
    ↓
Drive 执行状态机和当前模式
    ↓
debug_snapshot_publish() 复制本周期最终结果
```

发布点只有一处，位于 `fast_loop_step()` 的 `drive_fast_step(motor)` 之后。这样看到的是本周期控制执行完后的结果，而不是执行到一半的中间状态。

## 快照里有什么

| 分组 | 主要字段 | 含义 |
|---|---|---|
| 生命周期 | `req/state/pwm_on/fault` | Drive 请求、实际状态、软件 PWM 所有权和故障位图 |
| 模式 | `sys_mode/op_mode` | 当前系统模式，以及该系统模式对应的子模式 |
| 采样 | `v_bus/i_a/i_b/i_c/theta_e` | 母线电压、三相电流和电角度 |
| 位置速度 | `pos_r_ref/pos_r_fbk/vel_r_ref/vel_r_fbk` | 转子侧目标与反馈 |
| dq 电流 | `i_d_ref/i_d_fbk/i_q_ref/i_q_lim/i_q_fbk` | 电流目标、级联环限幅结果和反馈 |
| FOC 输出 | `v_d_cmd/v_q_cmd/duty_a/b/c` | dq 电压指令和三相候选占空比 |

`i_q_ref` 和 `i_q_lim` 分开保留：电流模式直接使用前者，速度/位置模式实际使用速度环计算并限幅后的后者。如果合成一个字段，会把不同控制模式的真实数据流藏起来。

`pwm_on` 是 Drive 的软件状态，不是 TIM 寄存器回读；`duty_a/b/c` 是 FOC 候选值，也不等于此刻示波器看到的真实桥臂波形。观察时必须结合 Drive 状态一起判断。

## 为什么不继续用 pm.display

原来的 `pm.display` 和 `pmsm_ctrl_display()` 目前没有生产调用，而且复制时还会根据电机极性改变符号和角度。它缺少 Drive 状态、故障、dq 目标和占空比，也容易把“显示换算”与“控制真值”混在一起。

因此本节点不删除它，也不改它，只建立一份含义明确的原始控制快照。Legacy 显示结构以后在清理确认点统一处理。

## 为什么暂时不接 VOFA 和 USB

当前 VOFA 代码读取的是另一组原始 ADC 字段，USB 接收也没有稳定的控制命令解析。现在直接接入会同时改变信号单位、通信协议和中断负担，超出这个节点。

本次只建立数据边界：以后 VOFA、离线记录或回放若需要数据，只能从稳定快照或专门采集接口读取，不应反向写 Drive/Control。

## 一致性边界

- `seq` 在其余字段复制完成后最后递增，可用于判断是否发布了新样本；
- 当前每个字段都是 32 位标量，快照总大小固定为 104 B；
- 停核后用调试器观察，可以得到完整稳定的一份数据；
- 运行中异步读取可能跨越两个控制周期，本节点不承诺整包原子一致；
- 没有为尚不存在的运行时消费者增加锁、双缓冲、环形缓冲或通信协议。

真正连续采集和离线回放时，再根据采样率和消费者要求单独设计缓存与一致性方案。

## 怎样验证

新增 Host 测试直接编译生产 `debug_snapshot.c`，完成以下检查：

1. 给 `pm` 的每个来源字段写入不同数值，发布后逐字段、逐位比较；
2. 验证 debug、release、calibrat、halt 四类系统模式的子模式映射；
3. 连续发布，确认字段刷新且 `seq` 递增；
4. 反向修改 `g_debug_snapshot`，确认完整 `pm` 一个字节都没有变化；
5. 静态搜索确认生产发布点只有一处，Drive 和 Control 都不引用快照。

## 离线验收结果

| 检查项 | 结果 |
|---|---|
| CMake / Keil 用户源清单 | 36 / 36，一致 |
| Debug clean-first | 0 错误，26 个警告 |
| Release clean-first | 0 错误，26 个警告 |
| Host C11 / 调试快照字段与方向测试 | 通过 |
| Host C11 / FOC、PID/PDFF、Drive 回归 | 全部通过 |
| 生产发布点 | 1 处，位于 Drive 执行之后 |
| Drive / Control 对快照的引用 | 0 处 |
| `debug_snapshot_publish` 目标段 | RAM 地址区的 `.data`（输入段为 `.RamFunc`） |
| `g_debug_snapshot` | `.bss`，104 B |
| Debug ELF | text 187620 B，data 136 B，bss 10304 B |
| Release ELF | text 145532 B，data 136 B，bss 10304 B |

与上一个检查点相比，Debug text 增加 352 B，Release text 增加 224 B，bss 增加 104 B，data 不变。增加内容就是发布函数和固定快照对象。

## 这一步明确没有做什么

- 没有让调试快照控制启停、模式、参数或 PWM；
- 没有复用或删除旧 `pm.display`；
- 没有接入 VOFA、USB、CAN 或串口协议；
- 没有增加锁、双缓冲、环形缓冲和数据字典框架；
- 没有声称完成运行时原子快照或连续高速采集；
- 没有测量快速中断新增耗时，硬件 WCET 仍需后续上板测量；
- 没有执行烧录、上电或电机测试。
