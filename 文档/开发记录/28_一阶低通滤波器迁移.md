# 一阶低通滤波器迁移

## 一句话说明这一步

把一阶低通滤波器的状态和公式从 `common.h + motor/util.c` 迁入 `User/control/control_filter.*`，生产代码的 8 个初始化调用和 2 个逐拍运行调用全部切换到新接口。

滤波频率、系数公式、初值和每一拍运算顺序均未改变。

## 新模块负责什么

```c
filter.fs = 20000.0f;
filter.fc = 200.0f;
control_lpf_init(&filter);

filtered_value = control_lpf_step(&filter, new_value);
```

`lpf_t` 仍保留原来的 6 个 `float` 字段：当前输入、当前输出、采样频率、截止频率和两个滤波系数。只是类型定义从总头移到了它真正所属的 Control 头文件，字段顺序和内存布局没有变化。

## 当前生产用途

- 初始化 d/q 电流、d/q 电压、母线电流、母线电压、电流幅值和转速共 8 个滤波器；
- 快速反馈更新中，实际运行 q 轴电流滤波和转子速度滤波；
- 其余已初始化但当前未运行的滤波器保持原状，没有顺手删除或接入。

## 保留的数值行为

初始化仍按原顺序计算：

```text
wf = 2π × fc
filt_a = fs / (fs + wf)
filt_b = 1 - filt_a
val = 0
val_f = 0
```

每一拍仍按原顺序执行：

```text
val = 新输入
val_f = filt_b × val + filt_a × 上一拍 val_f
返回 val_f
```

本节点没有增加新的参数检查、频率修正或滤波器类型。

## 怎样验证

Host 测试直接同时编译 Legacy `motor/util.c` 和新 `control_filter.c`：

1. 使用实际工程参数 `fs = 20000 Hz`、`fc = 200 Hz` 分别初始化；
2. 比较 6 个字段的完整位模式，容差为 0；
3. 连续输入零值、正值、负值和阶跃值；
4. 每一拍比较返回值和完整滤波器状态，容差为 0；
5. 静态断言 `lpf_t` 仍由 6 个 `float` 组成。

## 离线验收结果

| 检查项 | 结果 |
|---|---|
| CMake / Keil 用户源清单 | 37 / 37，一致 |
| Debug clean-first | 0 错误，26 个警告 |
| Release clean-first | 0 错误，26 个警告 |
| 新旧 LPF 初始化与连续逐拍对比 | 通过，完整状态逐位相等 |
| 其余 Host 回归 | FOC、PID/PDFF、限幅、快照、Drive 全部通过 |
| `control_lpf_step` 目标段 | RAM 地址区的 `.data`（输入段为 `.RamFunc`） |
| `control_lpf_init` 目标段 | `.text` |
| Control 对 main/bsp/common/HAL/pm 的依赖 | 0 处 |
| Debug ELF | text 184340 B，data 136 B，bss 10304 B |
| Release ELF | text 144084 B，data 136 B，bss 10304 B |

与上一个检查点相比，text、data 和 bss 均未变化。生产路径替换为等价实现后，链接器没有保留未使用的旧滤波函数。

## 这一步明确没有做什么

- 没有修改 20 kHz 采样频率和 200 Hz 截止频率；
- 没有把一阶滤波升级为二阶、卡尔曼或其他算法；
- 没有删除 `motor/util.c` 中的 Legacy 对照函数；
- 没有启用当前未运行的其他滤波通道；
- 没有执行烧录、上电或电机测试。
