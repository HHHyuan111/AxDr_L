# 角度差分测速显式状态迁移

## 一句话说明这一步

把 `angle_speed_calc()` 内部隐藏的“上一拍角度”迁成 `pmsm_t` 中明确可见的 `elec_speed_diff` 状态，生产路径改用纯 Control 接口 `control_angle_speed_step()`。

测速公式和跨圈规则不变，变化的是状态归属：以前所有调用者暗中共用一份函数静态变量，现在每个电机/回放实例拥有自己的状态。

## 为什么这是架构问题

旧函数内部有两个 `static float`：

- 上一拍角度；
- 本周期角度差。

调用接口只写了“角度和频率”，看不出函数还依赖历史。如果未来同时跑两个电机实例、两条离线回放或 HIL 对照，两边会互相覆盖上一拍角度，得到错误速度，也无法从外部准确保存和恢复算法状态。

现在接口变为：

```c
speed_rad_s = control_angle_speed_step(&motor.elec_speed_diff,
                                       angle_rad,
                                       sample_frequency_hz);
```

历史状态随电机对象走，数据依赖一眼可见。

## 保留的计算顺序

```text
角度差 = 当前角度 - 上一拍角度
    ↓
大于 +pi 时减去 2*pi
    ↓
小于 -pi 时加上 2*pi
    ↓
角速度 = 角度差 × 采样频率
    ↓
保存当前角度，供下一拍使用
```

比较仍使用严格的 `> +pi` 和 `< -pi`，恰好等于正负 pi 时不回绕。常量数值、20 kHz 调用频率和电角速度到转子速度的后续换算均未改变。

现有固件只有一个全局 `pm`，新状态和旧静态变量都从零初始化；Drive 启停时也都不额外清零，因此单实例现有行为保持一致。

## 怎样验证

Host 测试直接编译生产 `control_speed.c`，覆盖：

1. 两个独立状态实例交错运行，确认互不串扰；
2. 普通连续正向角度变化；
3. 从小角度跳到接近 `2*pi` 的正向跨圈；
4. 从接近 `2*pi` 回到小角度的反向跨圈；
5. 恰好 `+pi` 和 `-pi` 的边界规则。

新实现的每条运算和 Legacy 原函数逐句对应。旧函数暂时保留但已无生产调用，等 Legacy 清理确认后再移出。

## 离线验收结果

| 检查项 | 结果 |
|---|---|
| CMake / Keil 用户源清单 | 38 / 38，一致 |
| Debug clean-first | 0 错误，26 个警告 |
| Release clean-first | 0 错误，26 个警告 |
| 普通、跨圈、边界测速向量 | 通过 |
| 双实例状态隔离 | 通过 |
| 其余 Host 回归 | FOC、LPF、PID/PDFF、限幅、快照、Drive 全部通过 |
| `control_angle_speed_step` 目标段 | RAM 地址区的 `.data`（输入段为 `.RamFunc`） |
| Control 对 main/bsp/common/HAL/pm 的依赖 | 0 处 |
| Debug ELF | text 184548 B，data 136 B，bss 10304 B |
| Release ELF | text 144124 B，data 136 B，bss 10304 B |

与上一个检查点相比，Debug text 增加 208 B，Release text 增加 40 B，Berkeley 汇总中的 data/bss 不变。`pmsm_t` 明确增加 8 B 测速状态；Legacy 函数的旧静态状态仍会随同一 `.RamFunc` 段暂时链接，清理后再核对最终净资源。

## 这一步明确没有做什么

- 没有修改测速公式、滤波、20 kHz 频率或单位；
- 没有在 Drive START/STOP 时新增状态清零；
- 没有处理参数辨识模块内部的其他函数静态状态；
- 没有删除旧 `angle_speed_calc()`；
- 没有执行烧录、上电或电机测试。
