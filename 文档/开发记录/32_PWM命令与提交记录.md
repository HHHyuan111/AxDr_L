# 开发记录 32：PWM 命令与提交记录

## 1. 本节点解决什么

FOC 原来只有 `dtc_a/dtc_b/dtc_c`，调试时看不出下面两件事：

1. 本快速周期是否真的生成了新的 PWM 命令；
2. 这组命令是否已经调用 Target 接口写入 PWM 比较寄存器。

本节点给这两步各留一份很小的记录，为后续离线回放、仿真/HIL 和硬件时序测量提供统一观察点。

## 2. 当前数据链

```text
快速周期 fast_seq
    -> Drive 清空本周期 pwm_cmd
    -> 选定控制模式计算三相占空比
    -> foc_pwm_commit 记录 pwm_cmd
    -> Target 写 PWM 比较寄存器
    -> 记录 pwm_commit
    -> 发布同一 fast_seq 的只读调试快照
```

字段含义：

- `pwm_cmd`：算法本周期要求写入的逻辑 A、B、C 相占空比；
- `pwm_commit`：最近一次已经完成 Target 寄存器写调用的逻辑三相占空比；
- `seq`：对应的快速周期编号；
- `valid`：该记录是否有效；
- `pwm_committed`：调试快照中，本周期是否发生过 PWM 提交。

`cmd` 是 command 的常用工程缩写。这里不用“物理生效”描述 `pwm_commit`，因为寄存器写入后究竟在哪个 PWM 更新点反映到引脚，仍要用示波器验证。

## 3. 保持不变的行为

- ADC 中断和快速周期入口不变；
- 编码器、电流采样和控制模式执行顺序不变；
- FOC 数学公式、控制参数和相序映射不变；
- `target_pwm_set_duty_ratios()` 的调用位置不变；
- ABC/ACB 接线下写入物理通道的顺序不变；
- 没有烧录、上电或依赖 Elmo 工装。

## 5. 后续怎么用

后续可以在不碰 FOC 公式的前提下，用相同的 `pwm_cmd` 接口接入：

- Host 离线回放；
- 软件仿真或 HIL Target；
- PWM 提交时序测量；
- 与 Elmo 的同输入、同输出数据对标。

本节点只建立数据合同，不提前实现这些工具，也不移动真实 PWM 写入时机。
