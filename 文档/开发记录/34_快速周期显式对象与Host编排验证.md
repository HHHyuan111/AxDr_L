# 开发记录 34：快速周期显式对象与 Host 编排验证

## 1. 本节点解决什么

原 `axdr_app_fast_step()` 在函数内部直接使用全局 `pm`。这样虽然能运行，但电脑端回放或仿真很难给它换一份独立的电机对象。

现在接口改为：

```c
void axdr_app_fast_step(pmsm_t *motor);
```

快速周期内部只使用调用者传入的 `motor`。STM32 ADC 回调仍然调用：

```c
axdr_app_fast_step(&pm);
```

因此，全局对象只在硬件中断边界被选中，应用编排本身可以在 Host 上使用普通测试对象。

## 2. 快速周期固定顺序

```text
fast_seq 加 1
    -> 编码器原始采样
    -> 位置与电角度更新
    -> ADC 原始采样和三相电流换算
    -> 母线、限幅、转矩与速度反馈更新
    -> Drive 状态和控制模式执行
    -> 同周期只读调试快照发布
```

本节点没有调整角度与电流采样先后，之前待定的硬件同步问题仍留给示波器和时序测量，不凭离线测试下结论。

## 3. Host 验证内容

新增 `tests/host/test_fast_loop.c`，使用 Fake 模块直接编译生产 `axdr_app.c`，验证：

- 初始化未放行时，不访问电机对象，也不增加周期编号；
- 放行后六个步骤严格按当前顺序各执行一次；
- 所有步骤接收到同一个调用者传入对象；
- 连续周期的 `fast_seq` 连续增加；
- STM32 ADC 回调只负责把固件全局 `pm` 交给快速周期入口。

## 4. 保持不变的行为

- ADC 回调入口不变；
- 初始化放行条件不变；
- 编码器、ADC、反馈、Drive 和快照的调用顺序不变；
- FOC 公式、参数、状态和 PWM 提交时机不变；
- 没有烧录、上电或使用 Elmo 工装。
