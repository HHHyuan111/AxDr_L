# 开发记录 36：电机对象前向声明与头文件减耦

## 1. 本节点解决什么

此前 `axdr_app.h`、`drive.h`、`drive_mode.h`、`drive_pwm.h` 和 `debug_snapshot.h` 都直接包含 `common.h`。任何模块只想声明一个 `pmsm_t *`，也会被迫看到完整电机对象、硬件头文件和大量旧类型。

本节点新增轻量头文件：

```text
User/motor/motor_fwd.h
```

其中只做一件事：

```c
typedef struct pmsm pmsm_t;
```

上述 App 与 Drive 对外头文件现在只包含 `motor_fwd.h`。真正访问 `pmsm_t` 字段的 `.c` 文件才显式包含 `common.h`。

## 2. 为什么这样做

- 头文件只暴露接口需要的最少信息；
- 修改 `common.h` 时，不会无意义地扩散到所有接口使用者；
- Host、离线回放和仿真代码可以先依赖 App/Drive 接口，不必引入 STM32 硬件定义；
- 依赖方向更直观：接口声明与完整实现细节分开。

## 3. 没有做什么

- 没有拆散 `pmsm_t` 的现有字段；
- 没有改变 `pmsm_t` 字段顺序和内存布局；
- 没有删除全局 `pm`；
- 没有改控制公式、状态、参数或硬件调用；
- 没有为了“纯粹”一次性重写全部旧模块。

当前策略是先把新增和核心接口从 `common.h` 的扩散中隔离出来，旧算法后续按实际迁移需求逐个处理。

## 4. 验证

新增 `tests/host/test_public_headers.c`，不包含 `common.h`，直接包含全部 App/Drive 对外头文件并以 C11 严格警告编译，验证前向声明边界有效。

完整结果：

- 全部九组 Host 测试：通过；
- CMake/Keil 用户源文件：40/40，一致；
- Debug：0 错误，25 警告；
- Release：0 错误，25 警告。
