# 开发记录 37：架构重构离线总验收

## 1. 验收结论

当前版本已经完成本轮“先搭科学框架、保持控制行为、建立离线验证”的目标，可以作为后续读代码和继续迁移的稳定起点。

本轮没有重写全部旧算法，也没有建立复杂通用框架。核心工作是把原来混在一起的快速编排、状态、模式、控制计算、PWM 执行、硬件访问和调试观察分开，并给关键边界建立可重复验证。

## 2. 当前实际架构

```text
STM32 ADC 注入完成回调
    -> App：fast_loop_step(motor)
        -> 编码器采样与位置更新
            -> Target Encoder：SPI/片选/原始计数
        -> ADC 采样与电流换算
            -> Target ADC：ADC 寄存器/DMA 原始计数
        -> control_cycle_input_t：本周期物理反馈
        -> control_cycle_step()
            -> 反馈更新
            -> Drive 状态机：STOP/START/RUN/FAULT
                -> Drive 模式分派
                -> control_loop_step()
                    -> 电压/电流/速度/位置主链
                    -> 纯坐标变换、FOC 核心、PID/PDFF、级联控制
                -> Drive PWM：相序映射、命令与提交记录
                    -> Target PWM：TIM1 物理通道
        -> control_cycle_output_t：状态、故障和逻辑三相占空比
        -> 同周期只读调试快照
```

## 3. 各目录职责

| 目录 | 当前核心职责 | 不应该放入的内容 |
|---|---|---|
| `User/app` | 快速周期顺序、初始化放行、只读快照 | FOC 公式、TIM1 寄存器、具体模式算法 |
| `User/drive` | 状态闭环、模式分派、PWM 执行边界 | ADC/SPI 寄存器、坐标变换公式 |
| `User/control` | 可在 Host 重放的纯算法与显式状态 | HAL、Target、全局 `pm`、动态内存 |
| `User/bsp/target_*` | 当前 STM32G474 的 ADC、编码器和 PWM 硬件适配 | 控制模式、相序策略、FOC 计算 |
| `User/motor` | 尚未完全迁移的电机对象、反馈换算和高级算法实现 | 新增硬件寄存器直连 |
| `tests/host` | 生产模块的电脑端行为验证 | 真实硬件结论 |
| `tests/legacy` | 仅用于迁移期逐位/逐拍对照的旧实现 | 生产固件链接 |

## 4. 已建立的关键合同

### 4.1 快速周期合同

- `fast_loop_step(pmsm_t *motor)` 显式接收对象；
- 只有最外层 STM32 回调选择固件全局 `pm`；
- 每次放行周期只增加一次 `fast_seq`；
- 当前执行顺序由 Host 测试固定。

### 4.2 控制算法合同

- 坐标变换、SVPWM、FOC 核心位于 `User/control`；
- 电流、速度、位置级联状态显式传入；
- 生产新实现与 Legacy 测试实现已做逐位或逐拍对照；
- Control 目录不包含硬件头文件，不调用动态内存。

### 4.3 Drive 合同

- `drive.c` 只处理请求、状态、故障和功率动作；
- `drive_mode.c` 只处理现有模式到算法函数的映射；
- 未实现模式保持明确空操作，不伪造功能；
- `drive_pwm.c` 负责 ABC/ACB 相序映射和 Target 提交。

### 4.4 PWM 与调试合同

- `pwm_cmd` 表示本周期算法希望写入的逻辑三相占空比；
- `pwm_commit` 表示最近一次完成 Target 寄存器写调用的逻辑三相记录；
- 调试快照与上述记录使用同一个 `fast_seq`；
- `pwm_commit` 不等同于“引脚已经物理生效”，硬件更新拍数需要示波器确认。

### 4.5 头文件合同

- App 与 Drive 对外头文件只依赖轻量 `motor_fwd.h`；
- 只有需要访问电机内部字段的 `.c` 文件包含 `common.h`；
- 当前不强拆 `pmsm_t` 内存布局，避免无收益的大改。

## 7. 尚未宣称完成的硬件事项

- 编码器角度与三相电流是否真正同拍；
- ADC 触发点、DMA 数据新鲜度和 PWM 更新点；
- 快速中断最坏执行时间和抖动；
- Gate/Break 故障链路；
- 电机上电、带载和极限工况；
- Elmo 同输入条件下的波形和性能对标。

这些项目必须在硬件条件具备后测量。本轮没有烧录、上电，也不依赖尚未完成的 Elmo 工装。

## 8. 后续带读顺序

稳定版本建议按下面顺序从 0 到 1 学习和复现：

1. `fast_loop.c`：先看一次控制周期到底按什么顺序运行；
2. `drive.c`：看电机为什么启动、运行、停止和进故障；
3. `drive_mode.c`：看运行请求如何选择 MIT、电流环、速度环或位置环；
4. `foc_drv.c`、`foc_core.c`：看采样怎样进入完整 FOC；
5. `control_cascade.c`：看电流、速度、位置三级怎样逐层给定；
6. `drive_pwm.c`、`target_pwm.c`：看逻辑占空比怎样最终写进 TIM1；
7. `debug_snapshot.c`：看怎样确认同一周期的输入、控制结果和 PWM 提交。

读懂这条主链后，再按需要学习参数辨识、观测器、齿槽补偿等高级模块，避免一开始被实验算法分散注意力。
