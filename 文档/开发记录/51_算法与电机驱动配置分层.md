# 算法与电机驱动配置分层

## 一、本次目标

把会随实验变化的算法参数和会随实物变化的电机、编码器、驱动板参数分开，
避免更换电机或新增算法时修改通用算法核心。

## 二、配置入口

### 1. 算法实验配置

文件：`firmware/AxDr_App/User/diagnostic/include/diag_algorithm_config.h`

当前分组包括：

- 电流环扫频；
- 定子电阻辨识；
- 偏置电流电感辨识；
- 极对数辨识；
- 编码器零位校准；
- 死区测试；
- 在线解耦和磁链观测选项。

新增诊断算法时，在该文件增加一组带单位的 `DIAG_` 参数，并在
`diag_runtime.c` 初始化对应算法的配置结构体。算法核心只接收参数包，不能
直接包含本项目配置头。

### 2. 电机与驱动器配置

文件：`firmware/AxDr_App/User/motor/motor_drive_config.h`

当前分组包括：

- 当前电机型号选择；
- FOC、电流环、速度环、位置环和速度测量频率；
- ADC、采样电阻、运放、母线分压、NTC 和硬件死区；
- 驱动保护阈值；
- 主动诊断任务的电流、电压硬上限；
- MA732、MT6816 编码器参数；
- PR60 和 2312S 电机参数。

主动诊断电流和电压限值目前保持为 0，表示实物条件尚未确认，主动任务不能
启动。首次上电前必须根据电源、驱动板和电机能力填写，不能直接使用理论 ADC
量程代替安全限值。

## 三、运行时数据流

```text
diag_algorithm_config.h
        ↓ 默认实验参数
diag_runtime.c
        ↓ 复制到各算法独立配置结构体
扫频、Rs、L、极对数、校准等通用算法

motor_drive_config.h + 当前电机对象
        ↓ 电机模型、编码器、周期和实物硬上限
drive_diag.c
        ↓ 生成统一采样并补齐安全边界
诊断算法参数包
```

参数在初始化时复制到 `g_diag.profile`，快速周期运行期间不反复读取配置宏，也
没有新增可写全局对象。

## 四、扫频通用化调整

- `20～2000 Hz` 现在是项目默认扫频范围，不再是算法核心写死的绝对范围；
- 通用算法只要求频率大于 0 且低于当前采样频率的一半；
- 删除只针对 `100～350 Hz` 的特殊等待时间；
- 所有频点的测量长度统一对齐完整正弦周期；
- 当前电流环直接使用未滤波的 `id/iq`，因此项目默认反馈滤波系数改为 0。

## 五、验证结果

- 正式代码规范检查：通过，104 个 C/H 文件；
- 主机 C11 测试：全部通过；
- CMake 与 Keil 用户源码清单：43 个，完全一致；
- Debug 固件：构建成功，生成 ELF 和 HEX；
- Release 固件：构建成功，生成 ELF 和 HEX；
- Debug/Release：均无编译错误和警告。

以上属于离线验证。PR60、MA732、电流采样极性和真实扫频响应仍需按首次上电
清单在实物上逐项确认。
