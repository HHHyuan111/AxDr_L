## 2. 建议阅读顺序

从 `main.c` 的 `main()` 开始看：

```c
/* 1. 采样启动、控制器初始化、参数恢复，然后放行电机快环。 */
app_motor_init();

/* 2. 连接通信服务，并显示初始电机状态。 */
app_services_init();
app_display_init();
```

后台循环调用 `app_background_poll()`，该函数按原顺序列出安全检查、观测状态、命令接收、数据准备、发送和参数保存。

电机计算不在后台循环执行。打开 `fast_loop.c`，沿四个步骤读到 `control_cycle_step()`；再打开 `control_cycle.c` 看本拍反馈如何进入 Drive，Drive 完成后如何做磁链观测和保存输出。

本次没有为每个操作增加转发函数。快环中的采样与输入字段仍直接可见，原有离线测试入口保持。

## 3. 样板采用的规则

1. 主流程按真实执行顺序写，同一函数保持相近的抽象层次。
2. 函数封装完整职责，不为缩短行数增加无意义转发。
3. 参考值、反馈值、输出值分清；单位、角度来源及有效性影响理解时明确写出。
4. 手写代码四空格缩进，独立大括号，逻辑段之间一个空行；短范围字段可以对齐。CubeMX 生成区域保持原格式和标记。
5. 源码注释说明当前行为、执行条件和原因，历史阶段编号与排障过程放在开发记录中。
6. 对实际控制周期说明输入、执行内容和输出；不为简单函数填空白模板，不逐行翻译赋值语句。
7. 中文注释和说明使用 UTF-8；英文标识符沿用项目现有命名，不批量重命名文件与接口。
8. Control 保持硬件独立；保护、启停、PWM 提交和并发约束不得为视觉简洁而隐藏或删除。
9. 纯编排整理与算法修复分开验证，不能把阅读改善写成算法或性能提升。

本轮未修改 AGENTS.md 或课程文字规范，也未把整个工程宣布为已完成风格统一。
