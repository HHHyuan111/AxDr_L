## 1. 本轮问题与范围

当前采样先写 `foc->fb`，快环再把反馈复制到 `input`，控制周期又写回 `foc->fb`。本轮只调整这一处职责边界：采样和换算返回本拍结果，控制周期负责装入本拍控制反馈。

沿用《主流程教学化整理_20261101》的编排规则和普通固件任务的协议、保护约束，无新增 SDD。实际工程为 `C:/Users/ready/Desktop/DriverLab/AxDr_L/firmware/AxDr_App`，不修改聊天默认目录的沉沙工程。

实现范围：快环、ADC 采样返回接口、位置换算返回接口及其定向测试。ADC 采样实现归入已有 `board_adapter.c`；位置的跨圈历史仍保留在现有字段中，不拆分或重命名 `foc_t`。位置、电流、母线的新控制值通过结果对象交给 `input`；历史值与原始计数仍由采样适配层维护。

采样顺序、换算公式、无效时保留旧值、有效性标志、控制/保护/观测顺序保持。测速已知边界、命令一致性、模式和无感功能不混入本轮。仅离线验证，不烧录、不连接板端、不提交或推送。

## 2. 验证方法

假设：去掉新反馈在 `fb` 中的中转，可以使采样到控制的方向明确，同时保持本拍结果和历史状态。

通过标准：

1. 同一组 ADC、编码器和有效性输入，换算结果与冻结旧实现一致；正反跨圈、偏置、减速比和无新样本均覆盖。
2. 快环正常与失败分支保持执行顺序；新值在控制周期前不写入实时控制反馈，失败时保留旧数值并传递原有无效标志。
3. 相关 Host C11 检查、ARM 构建通过，既有改动完整保留；资源变化如实记录，离线检查不代替实机时序验收。

## 3. 结果与下一停点

本轮数据流为：

```text
编码器读取 → 位置换算 → pos ┐
                           ├→ input → control_cycle_step → foc->fb → 控制与 PWM
ADC 读取 → 相序/零偏换算 → adc ┘
```

`pos` 和 `adc` 是本拍的局部结果；初始化为上拍数值，在采样失败时保留。`i_valid`、`pos_valid` 继续告诉控制周期本拍是否有效。母线的 `vbus_valid = true` 沿用旧规则，本轮没有新增母线有效性判定。

位置换算需要记住上一拍角度和转过的圈数，这些历史字段仍保留在 `fb`，原始计数仍保留在 `adc.raw`。本轮去掉的是新电流、母线电压、电角度和多圈控制位置的中转，不能理解为采样阶段不再修改任何历史字段。已有结构体及成员未重命名，未改动内存布局或协议。
