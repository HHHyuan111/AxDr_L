# 分阶段迁移与验证计划

文档状态：待执行方案

## 一、依据和范围

本计划只依据当前源码、工程配置、构建基线、用户目标、课程功能范围和有效编码规范制定，不使用已排除的架构预研材料。

总体边界：

- `AxDr_App` 是当前主工程。
- `1.AxDr_Drag_VF` 只作为历史参考。
- STM32Cube 生成区、`Drivers` 和 `Middlewares` 原则上不做架构性改写。
- 未建立行为基线前，不做大规模改名、目录搬迁、算法改写或参数调整。
- 当前阶段不依赖 Elmo 工装，不执行带功率验证。

## 二、每一步的统一规程

开始修改前先记录：

1. 本步目标；
2. 允许修改的目录、文件和接口；
3. 明确不改变的行为；
4. 构建、测试、数据和安全验收条件；
5. 回退依据和基线产物。

修改完成后依次执行：

1. ARM GCC 从空目录构建；
2. ArmClang 兼容性检查或 Keil 构建；
3. 主机测试和数值比较；
4. 条件具备且通过安全准入后再执行上板测试；
5. 记录工具版本、命令、结果、警告、固件尺寸和偏差。

格式整理、机械改名、架构移动、算法行为变化和参数调整不得混在同一变更中。

## 三、阶段计划

### 阶段零：固化现状基线

目标：固定源码、工具链、历史产物、实时链路、安全风险和已知问题。

改动边界：只增加中文盘点和基线记录，不改原始工程。

验收结果：已完成。完整重新构建和可运行测试被记录为已知阻塞，不伪装成通过。

### 阶段一：恢复可重复构建

目标：从空目录稳定生成 ARM 固件，并建立最小主机 C11 测试外壳。

允许改动：

- CMake 源码清单、预设、工具链加载和产物生成规则；
- 已被编译检查证实的最小兼容问题；
- 主机测试入口、构建清单校验和依赖扫描。

本阶段不改变：控制公式、参数数值、外设时序、启动顺序、PWM 行为和运行模式。

首批确定性问题：

- CMake 补入 `User/moldue` 头文件和源文件；
- 消除预设与顶层脚本对工具链文件的重复加载；
- 修正 `encoder.c` 的 SPI 接收缓冲区类型；
- 处理 `lcd.c` 中不符合 C11 的空数组；
- 处理无返回值函数、未初始化局部变量和标准数学宏重定义；
- 建立显式源码清单，避免递归通配隐藏差异。

验收条件：

- 从空构建目录生成 ELF、HEX 和 MAP；
- 连续两次完整构建成功；
- 项目自有代码没有新增警告；
- ArmClang 语法基线不退化，安装匹配 DFP 后补做 Keil 完整构建；
- 主机冒烟程序和 CTest 可以运行且不包含 STM32 头文件；
- CMake 与 Keil 的生产源码集合可以自动比较；
- 不覆盖已有 Keil 历史产物。

### 阶段二：建立行为特征测试

目标：在移动算法前锁定现有关键数值行为。

改动边界：增加测试适配器、输入向量、期望输出、容差登记和必要的确定性修复。

验收条件：

- 坐标变换、调节器、限幅、调制、轨迹等具有边界和基准用例；
- 零分母、无效输入、NaN、Inf、饱和和复位行为有测试；
- ARM GCC、ArmClang 和主机结果在事先登记的容差内一致；
- 行为差异被分类为缺陷修复或有意变化，不静默接受。

### 阶段三：建立公共数据契约和虚拟板级层

目标：建立周期、采样、反馈、命令、输出、实际执行结果、参数和报告契约，使硬件可以被虚拟实现替代。

改动边界：新增窄接口、显式上下文、虚拟板级实现和旧代码兼容包装。

不做事项：不更换估算器、不调整控制参数、不实现高级单电阻算法。

验收条件：

- 公共契约可在主机 C11 下独立编译；
- 第一个周期、无效输入、限幅、Gate 禁止和上一周期实际输出测试通过；
- 新模块没有新增可写全局状态；
- 虚拟采样能够表达三电阻和未来单电阻所需的采样点、窗口和有效状态。

### 阶段四：重构运行引擎和安全输出权

目标：把状态、模式、启动阶段、反馈来源、故障处理和快慢周期编排从 HAL 回调中抽离。

改动边界：运行引擎、完整命令收件箱、一致只读报告、板级限幅和 Gate 决策；旧算法继续通过适配接口调用。

验收条件：

- 停止、反转、启动、反馈丢失、无效采样、故障和恢复的状态表测试通过；
- 上电、复位和故障清除后的第一周期不请求 PWM；
- 命令压力测试不存在字段撕裂；
- 状态、故障、诊断和实际输出具有同一个发布序号；
- 即使运行引擎本周期失败，板级层仍可强制安全输出；
- 快速中断中没有阻塞原语。

### 阶段五：逐模块抽离可移植算法

建议顺序：

1. 数学工具和坐标变换；
2. 调节器和限幅器；
3. Clarke、Park 及逆变换；
4. 调制候选计算，不包含硬件写入；
5. 电流环；
6. 速度和位置测量及控制环；
7. 轨迹和参考量处理；
8. 编码器角度处理；
9. 每个估算器独立迁移；
10. 在实验流程分离后迁移参数辨识与标定算法。

每个模块的验收条件：

- 不依赖 HAL、板卡和总头文件；
- 基准、边界和回放测试通过；
- 两个上下文交错初始化、复位和执行时互不污染；
- 主机和 ARM 使用同一源码；
- 不同时进行参数调整或无关格式化。

未完成的 IPD、HFI 或估算器实现先留在实验区，不能因文件存在就进入发布构建。

### 阶段六：数据采集、离线回放和仿真

目标：使每次实验可以复现，并让离线证据成为平台正式能力。

改动边界：版本化记录格式、非阻塞记录器、数据集目录、回放程序、电脑模型和半实物接口。

验收条件：

- 每条记录包含实验编号、周期/时间、完整命令、反馈、请求、实际输出、状态、故障、有效性、构建/参数/标定身份；
- 记录到回放可以重现离散状态和故障序列；
- 格式、单位或版本不匹配时明确拒绝；
- 仿真只替换模型和板级环境，不重写控制算法；
- 同一场景可以在没有目标硬件时运行。

### 阶段七：参数辨识、自整定和对标接口

目标：建立受控实验、候选参数和统一设备对标流程。

验收条件：

- 辨识结果记录单位、工况、可信度、数据集和算法版本；
- 结果只进入候选参数包，不能隐式修改活动参数；
- 自整定对固定输入产生可重复、可审核和可回退的候选结果；
- 对标程序可以比较两份离线数据或自研驱动与电脑模型；
- Elmo 适配器缺失时，主工程仍能构建和测试。

### 阶段八：板级资格验证

进入条件：前述离线门全部通过，确认实物板修订号和引脚表，具备低压限流装置和批准的安全流程。

实测验收：

- 六路 PWM 极性、互补关系和有效死区；
- CH4 到 ADC 的真实采样时刻、顺序和有效窗口；
- Break/Gate 路径和最坏故障关断时间；
- 快速中断最坏执行时间、抖动、嵌套和栈高水位；
- RAM、Flash 和栈预算；
- 通信快照一致性和数据丢失行为；
- 先进行低压限流场景，再考虑更高能量运行。

Elmo 实物对标在本阶段之后接入，不改变核心架构的验收条件。

## 四、主要风险及控制措施

| 风险 | 控制措施 | 退出条件 |
|---|---|---|
| 没有 Git 历史 | 保留哈希和只读输入，优先建立版本控制 | 任一修改均可定位和回退 |
| 两种编译器行为不同 | ARM GCC 与 ArmClang 双检查 | 项目自有代码在两者下均无错误 |
| 没有自动测试 | 先建立特征测试再移动算法 | 每个被迁移模块均有数值基线 |
| 算法依赖全局 `pm` 和 HAL | 逐步引入上下文和窄输入输出 | 算法目录不直接访问硬件 |
| 无硬件运行条件 | 使用主机测试、历史产物和离线数据推进 | 架构阶段不被硬件缺失阻塞 |
| 单位和容差未统一 | 数据契约强制登记单位、周期和容差 | 每项比较具有明确判定规则 |
| Elmo 工装未完成 | 只定义主机端适配和数据映射 | 固件及核心测试不链接 Elmo 实现 |

## 五、当前下一步

下一步是阶段一“恢复可重复构建”。开始修改源码前需要先确认：

1. `AxDr原始代码` 是否固定为只读参考；
2. `Driver_lab` 是否作为新源码工作树；
3. 版本控制是在 `Driver_lab` 新建，还是接入用户另行提供的真实仓库历史。

确认后，第一笔代码变更只处理构建清单和已验证的编译兼容问题，不改变算法参数、不改变硬件时序、不烧录设备。
