# 程序架构与状态机设计评审表（草案）

> 用途：发给同事评审整体方向。表中“当前情况”是现有代码事实，“目标设计”是候选方案，尚未冻结，也不代表已经实现。建议在“同事意见”栏填写“同意 / 修改建议 / 暂缓”。

## 一、总体结论表

| 评审项 | 当前情况 | 目标设计 | 同事意见 |
| --- | --- | --- | --- |
| 重构方式 | 已在原源码受控副本上渐进修改，原始代码保持只读 | 继续小步迁移，不重写整套 FOC，不一次性搬目录 |  |
| 核心分层 | 已初步建立 PWM、ADC、编码器板级适配；其余职责仍混在 `pm`、`common.h`、`foc_ctrl.c` 和 `foc_drv.c` | `Composition → Target / App / Drive / Comm`，`Drive → Control`，各层通过公共数据合同交换 |  |
| 实时主链 | ADC 回调直接组织采样、反馈、状态机、FOC 和 PWM | 固定为“采集 → 换算 → 状态/控制 → 输出请求 → Target 裁决 → 发布快照” |  |
| 硬件输出权 | PWM 寄存器写入已收拢到 `target_pwm`，Gate、Break 和最终安全许可尚未完成 | 只有 Target 可以写 PWM、MOE、Gate 和处理 Break；其他层只能提出请求 |  |
| 状态机 | Legacy 状态机已整理到可读，但请求、状态、停车、标定和实验模式仍有混合 | 生命周期状态、控制模式、启动阶段、停车策略、角度来源和实验任务分别建模 |  |
| 控制算法 | Clarke/Park、PI、FOC、SVM、轨迹和观测器仍依赖完整 `pm` | 每个算法采用 `config/state/input/output`，提供 `init/reset/step`，不包含 HAL 和寄存器访问 |  |
| 调试与数据 | VOFA、显示和调试字段仍可能直接读取大对象，没有一致周期快照 | 调试只读取 Snapshot/Trace；开关调试不得改变控制结果 |  |
| 回放与仿真 | 尚未建立 | Replay、电脑模型和 HIL 复用同一份 Drive/Control C 源码，只替换硬件与被控对象 |  |
| Elmo 对标 | Elmo 工装尚未完成 | Elmo 只作为电脑端可选适配器；没有 Elmo 时固件、回放和仿真仍可独立完成 |  |

## 二、整个程序分层评审表

| 层级 | 大白话职责 | 当前代码对应及进度 | 目标边界 | 主要输入 → 输出 | 需要同事确认 | 同事意见 |
| --- | --- | --- | --- | --- | --- | --- |
| `AxDr_App` 生成外壳 | 保存 CubeMX、HAL、启动文件、链接脚本和少量 USER 调用点 | 已存在；`main.c` 仍直接启动采样、PWM 和业务初始化 | 不放 FOC、状态机、实验策略和遥测字段选择 | 复位与生成配置 → 已初始化外设 | CubeMX 重新生成后的维护方式；业务初始化应该放在哪个 USER 钩子 |  |
| `composition` 装配层 | 把所有模块接起来，固定初始化顺序和快慢任务顺序 | 尚未独立；目前由 `main.c` 和 ADC 回调承担 | 只负责创建静态实例、绑定句柄和安排调用，不实现算法 | 各层实例 → 完整周期调用 | ADC/中断/PWM/电机对象的正确启动顺序 |  |
| `target` 板级层 | 与 STM32G474、ADC、PWM、编码器、Gate、Break 打交道 | 已有 `target_adc`、`target_encoder`、`target_pwm` 薄适配 | 独占硬件采集和最终输出；不执行 FOC、速度环或实验策略 | 硬件事实 + 输出请求 → 采样、物理反馈、实际提交结果 | 板卡版本、引脚、死区、Break/Gate/Ready、ADC 与 PWM 时序 |  |
| `drive` 运行引擎 | 决定当前能否运行、运行哪个阶段，并组织每个控制周期 | Legacy 状态机和模式入口已完成可读性整理，目标 Drive 尚未建立 | 不读 ADC 寄存器、不写 PWM；独占生命周期和周期编排 | 反馈 + 命令 + 故障 → 状态 + Control 输入 + 输出请求 | 状态表、事件优先级、启动/停车条件、命令超时 |  |
| `control` 纯算法层 | 真正计算角度、PI、FOC、轨迹、观测器和 SVM | 算法已存在，但仍依赖 `common.h`、完整 `pm`，并与输出提交相连 | 只做计算，无 HAL、通信和硬件副作用；支持独立初始化、复位和单步 | 配置 + 状态 + 本拍输入 → 本拍输出 + 诊断 | 第一批先迁电流环、速度环还是数学变换；数值容差如何确定 |  |
| `app` 应用层 | 接收用户意图，决定命令来源、模式请求、参数切换和实验计划 | 命令、模式和实验配置仍散落在 `pm` 和通信代码中 | 不直接修改控制器历史或 PWM；只提交完整命令和离散事件 | 外部命令 → 已校验命令、事件、实验计划 | CAN/USB/本地命令优先级、授权、超时和旧命令失效规则 |  |
| `config` 参数与标定 | 管理电机、板卡、PI、标定参数的版本、校验、激活和回退 | 当前主要在初始化函数和大结构体中直接赋值 | Fast 只读取一整份稳定参数；辨识和自整定只产生候选参数 | 参数输入 → 候选版本 → 安全状态下激活版本 | 参数格式、CRC、Flash 双槽、掉电恢复、版本回退 |  |
| `contracts/foundation` 公共合同 | 规定跨层数据长什么样，以及单位、方向、周期和有效性 | 尚未正式建立；目前主要通过 `pm` 字段共享 | 只描述数据，不保存算法私有状态和寄存器；每类数据只有一个写者 | 原始采样/反馈/命令/请求/提交/快照 | 电流、电压、角度、速度的单位和正方向；周期序号如何定义 |  |
| `comm` 通信层 | UART、USB、FDCAN、VOFA 的协议收发 | 已有旧实现，但观察数据仍缺少统一只读边界 | 只能向 App 提交命令，或消费 Snapshot/Trace；不能访问 Drive 私有对象 | 原始报文 ↔ App 命令 / 只读遥测 | 第一版保留哪些协议和最小字段；发送拥塞怎样丢帧但不阻塞控制 |  |
| `snapshot/trace` 观察层 | 把同一控制周期的输入、状态、输出和故障记录下来 | 尚未建立正式快照和环形记录 | 固定容量、非阻塞、只读发布；显示和调试不能反向参与控制 | 本拍事实 → 快照、记录、故障冻结数据 | 第一批必需记录字段、采样分频、容量和丢帧统计 |  |
| `verification/workstation` 验证与电脑端 | 做单元测试、回放、模型、HIL、数据分析和设备对标 | 已完成 ARM GCC Debug/Release 构建；回放、Fake Target 和 HIL 尚未建立 | 复用生产 Drive/Control 源码；电脑模型只替代电机和硬件环境 | 场景/数据/参数 → 测试结论和中文报告 | Golden 数据来源、Host 工具、Simulink 角色、HIL 和 Elmo 接入时间 |  |

## 三、目标快速控制周期表

| 顺序 | 责任层 | 本周期动作 | 产生的数据 | 当前对应 | 同事意见 |
| --- | --- | --- | --- | --- | --- |
| 1 | Target | 锁存本周期 ADC、编码器和硬件故障事实 | 原始采样 + 周期号 + 有效性 | `target_adc`、`target_encoder` 已有薄接口 |  |
| 2 | Target/可移植传感器处理 | 完成零偏、比例、方向、角度和速度换算 | 统一单位的物理反馈 | `foc_adc_sample()`、位置与反馈更新仍在旧结构 |  |
| 3 | Drive | 锁存完整命令，推进生命周期、故障、启动和停车状态 | 本周期 Control 输入和功率许可 | Legacy 状态机仅完成可读性整理 |  |
| 4 | Control | 执行位置环、速度环、电流环、变换和 SVM | 电压或占空比候选请求 | 现有 FOC 算法 |  |
| 5 | Target | 复核 Break、Gate、母线、采样有效性和输出范围，决定接受、限幅或拒绝 | 实际提交结果和拒绝原因 | `target_pwm` 目前只负责占空比写入 |  |
| 6 | Drive | 根据 Target 实际接受结果更新需要闭环确认的状态 | 一致的运行状态和算法历史 | 尚未建立 |  |
| 7 | Snapshot/Trace | 发布同周期反馈、命令、请求、实际提交、状态和故障 | 可调试、可回放记录 | 尚未建立 |  |

实时周期内不做：动态内存、Flash 擦写、LCD 刷新、阻塞通信、字符串格式化、等待锁和无界循环。

## 四、目标状态机评审表

> 状态名称来自候选目标方案。当前只评审状态含义和边界，不在同事确认前直接按表改代码。

| 目标状态 | 大白话含义 | 功率输出 | 主要进入条件 | 正常退出方向 | 异常方向 | 当前代码近似项 | 需要同事确认 | 同事意见 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `BOOT` | 刚复位，先建立最小安全软件环境 | 禁止 | MCU 复位 | `SELF_TEST` | `FAULT_ACTIVE` | 无独立状态 | BOOT 完成标志、超时和复位来源处理 |  |
| `SELF_TEST` | 检查配置、内存、传感器和 Target 基本条件 | 禁止 | BOOT 完成 | `DISABLED` | `FAULT_ACTIVE` 或 `FAULT_LATCHED` | 无独立状态 | 是否必须单独成状态；首版自检项目有哪些 |  |
| `DISABLED` | 系统正常，但明确禁止功率输出 | 禁止 | 自检完成、正常停机或故障确认完成 | `CALIBRATING` 或 `READY` | `FAULT_ACTIVE` | `reset/stop` 只能近似对应 | 与 READY 的区别；如何证明 MOE/Gate 已关闭 |  |
| `CALIBRATING` | 做不需要桥臂带电的零偏和静态传感器标定 | 禁止 | 合法的无功率标定请求 | `DISABLED` 或 `READY` | 硬件异常时 `FAULT_ACTIVE` | 当前 `calibrat_mode` 的一部分 | 哪些现有任务归这里；取消、超时和结果保存规则 |  |
| `READY` | 参数、反馈和硬件条件已满足，等待运行请求 | 禁止 | 无活动故障，参数和反馈有效，Target 条件满足 | `STARTING` 或 `COMMISSIONING` | `FAULT_ACTIVE` | `prech` 不能直接等同 | READY 的完整准入条件；是否预装中点占空比 |  |
| `COMMISSIONING` | 受控带电实验，例如辨识、编码器电气偏置和齿槽标定 | 按授权包络允许 | READY + 任务授权 + 电流/电压/速度/时间上限 | `STOPPING` 或 `READY` | 安全条件失效时进入故障 | 当前带电标定/辨识混在 `calibrat_mode` | 哪些任务允许带电；授权、取消、超时和候选参数审批 |  |
| `STARTING` | 执行对齐、开环拖动或其他受控启动阶段 | 条件允许 | READY + 运行请求 + 启动条件满足 | `RUNNING` | 取消去 `STOPPING`，严重异常去故障 | `start/prech` 只能粗略对应 | 启动阶段、每阶段完成条件和超时 |  |
| `RUNNING` | 正常执行电压、电流、转矩、速度或位置控制 | 条件允许 | STARTING 成功且无活动故障 | `STOPPING` | 按故障动作进入停车或立即故障 | `opera/runing` | 支持哪些控制模式；模式切换是否允许在线完成 |  |
| `STOPPING` | 按指定策略减速、滑行、制动或立即关断 | 由停车策略决定 | 正常停止请求或受控停车故障 | 正常去 `READY` 或 `DISABLED` | 故障仍活动去 `FAULT_ACTIVE`，已消失去 `FAULT_LATCHED` | 当前 `halt_mode`，但没有独立状态 | 正常停车最终去向；完成阈值、超时、再生吸能条件 |  |
| `FAULT_ACTIVE` | 故障源现在仍然存在 | 禁止 | 活动 Trip 或立即关断条件 | 故障源消失后 `FAULT_LATCHED` | 更严重故障继续保持 | 当前单一 `fault` 的一部分 | 哪些故障必须立即关断，哪些允许受控停车 |  |
| `FAULT_LATCHED` | 故障源已消失，但必须人工或授权确认 | 禁止 | 活动故障消失但历史故障需保留 | 确认成功后 `DISABLED` 或 `READY` | 故障重新出现回 `FAULT_ACTIVE` | 当前没有独立对应 | 确认权限、关闭证据、确认成功后的目标状态 |  |

## 五、不能再混进生命周期状态的独立维度

| 独立维度 | 建议内容 | 为什么分开 | 同事意见 |
| --- | --- | --- | --- |
| 控制模式 | 电压、电流/转矩、速度、位置 | `RUNNING` 只表示生命周期，不应该等同某一种算法 |  |
| 给定方式 | 直接给定、轨迹给定、周期同步给定 | 给定生成方式不应该改写功率状态 |  |
| 启动策略与阶段 | 对齐、开环、编码器直接闭环、估算器捕获等 | STARTING 内部可以有多种策略，但仍属于一个生命周期 |  |
| 停车策略与原因 | 滑行、受控减速、主动制动、立即关断；正常/故障/超时 | 停车动作和进入停车的原因需要分别记录 |  |
| 角度来源 | 编码器、Hall、估算器、开环角度 | 反馈来源可以切换，但不能伪装成控制模式或状态 |  |
| 实验任务与阶段 | 参数辨识、编码器标定、齿槽标定及其准备/激励/收尾 | 实验有独立授权和包络，不能靠 `debug_mode` 绕过状态机 |  |
| 故障动作 | 告警、限幅、受控停车、立即关断、掉电锁定 | 同一种生命周期中，不同故障需要不同响应 |  |
