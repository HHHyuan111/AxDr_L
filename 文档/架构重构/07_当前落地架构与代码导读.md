# 当前落地架构与代码导读

更新：2026-11-01，普通固件的持久状态机与命令、测速修正。源码与离线检查状态见 [本轮任务记录](../开发记录/持久状态机与命令测速修正_20261101.md)，本轮没有烧录或实机验收。

## 1. 从哪里开始读

先打开 `firmware/AxDr_App/User/app/control_cycle.c`，读文件前面的 `control_cycle_step`。它按顺序列出一拍 FOC 的七步。反馈对象的组装在文件后面的 `foc_read_feedback` 内，先看主流程时不必展开。

```text
ADC1 注入转换完成（20 kHz）
  → fast_loop_step：检查初始化放行、递增周期编号
  → foc_run：选择硬件输入，进入共用的 control_cycle_step
      1. foc_read_feedback       读取反馈
      2. drive_check_protection  检查保护
      3. drive_update_state      更新运行状态
      4. drive_handle_state      处理对齐/诊断，生成模式给定和控制角度
      5. foc_update_current      Clarke/Park，更新电流与角度
      6. foc_execute             控制器计算，再做调制
      7. drive_output            校验并输出 PWM，处理停机
  → 磁链观测、只读快照与周期记录
```

第 5、6 步只在有本拍给定且未锁存故障时执行。`foc_run` 是硬件入口，显式输入测试直接调用 `control_cycle_step`，两者共用这段代码。生产代码已退役旧 `drive_fast_step` 调度和旧 `foc_*_step` 单模式包装，没有另一套运行主链。

## 2. 状态决定能否运行，模式决定如何计算

`drive.c` 中先选择本拍状态，再处理动作。参考 iFOC 的状态进入条件及状态/模式区分，使用静态 C 分支，不引入它的 C++ 动态任务注册。

| 持久运行状态 | 主要动作 | 原协议状态 |
|---|---|---|
| `STOP` | 关闭输出，等待启动 | `STOP=0` |
| `STARTING` | 模式和保护允许后，先写 50% 中性占空比再开启；下一拍控制 | `STARTING=1` |
| `ALIGN` | ABZ 未对齐时生成渐变电流和扫描场角；完成后停机 | `STARTING=1` |
| `RUN` | 生成 VF、IF、电流、速度、位置等模式的给定 | `RUN=2` |
| `DIAG` | 运行已接入的诊断，检查诊断电压边界 | `RUN=2` |
| `FAULT` | 关断、保持故障，等待显式清除 | `FAULT=3` |

运行状态只保存在 `foc->state`；`drive_cycle_t` 只保存本拍给定和计算结果。`drive_update_state` 判断转换条件，`drive_enter_state` 集中做进入动作，`drive_handle_state` 处理本拍给定。协议兼容映射只放在服务层。对齐完成后不会自动进入速度/电流运行，必须再次显式启动。

`drive_mode.c` 负责选择模式，`motor_modes.c` 负责轨迹、单位换算和给定。它们只填 `foc_plan_t`，不执行 PI、不写 PWM。`theta` 表示本拍控制用的场角：普通有感闭环取编码器角度，VF/IF 取积分场角，对齐取校准场角。

## 3. 文件各管什么

| 目录/文件 | 责任 | 不负责 |
|---|---|---|
| `app/fast_loop.c` | 初始化放行、周期编号、保存观测 | 组装控制输入、选择模式 |
| `app/control_cycle.c` | Runtime：一拍执行顺序、选择硬件或显式输入 | PI 公式、寄存器操作 |
| `drive/drive.c` | 状态条件、启停、对齐、输出关口 | Clarke/Park、PI 公式 |
| `drive/drive_mode.c`、`motor/motor_modes.c` | 选择控制模式、轨迹和给定 | 直接提交占空比 |
| `motor/foc_drv.c` | 初始化、反馈派生量、`foc_t` 与可移植控制器的映射 | 运行状态调度 |
| `control/foc_control.c` | 电压/电流/速度/位置控制与调制编排 | HAL、全局电机对象 |
| `control/foc_core.c`、`algorithm` | 坐标变换、PI、限幅、SVPWM 等计算 | 运行请求、硬件使能 |
| `adapter` | 原始采样换算到 A/V/rad，编码器位置/速度适配 | 控制模式选择 |
| `bsp/target_*` | 原始 ADC/编码器读取和实际 PWM 操作 | 控制量换算、PI |

`foc.h`、Drive 对外头文件继续使用不完整对象指针；本拍内部类型分别放在 `foc_run.h`、`drive_cycle.h`，不要求服务层包含整套控制器定义。没有批量改名或移动文件；`foc_t` 原成员偏移保持，末尾追加独立测速上下文。

## 4. 保护和输出怎样检查

三相电流、母线电压、编码器有效性和启动方向先进入保护。速度保护使用本拍已更新的速度；滤波转矩仍沿用原先的 dq 反馈时序，本轮不调整滤波算法或采样时序。

普通控制占空比只在 `drive_output` 里提交，再由 `drive_pwm.c` 检查有限值、0～1 范围及相序，最后由 Target 写比较寄存器。启动前写 50% 是进入启动状态的专门动作。无有效计算、无效相序或故障不会继续沿用上一拍功率输出。

对齐的本拍给定在第 4 步生成，计算与输出走共用步骤，取样/定零收尾仍在本拍输出后处理。对齐计算失败或提交被拒绝时，停止并清空未完成的进度。硬件停机失败则保留 FAULT 和活动状态，不能把它报告为安全关闭。

检查方法：状态/对齐失败注入、七步调用顺序断言、真实控制数学与 PWM 替身的连续输入对照。引脚实际关闭延迟、20 kHz 中断占用必须后续上机测量，离线通过不能替代这些结果。

## 5. 当前能力与后续范围

源码已接入 VF、IF、电压、电流、速度和位置调试模式，MIT、PV、PP、CST、CSV、CSP、Quick Stop，以及已有统一诊断入口。接入源码不等于每个模式都经过当前板端验收。模式可执行表以 `drive_mode_is_supported` 为准。

当前磁链观测在控制后运行，没有接管电角度，不能称为完整无感闭环。温度 ADC 尚未接入保护有效数据。本轮已经修正测速初始化与丢样恢复边界，并用短临界区发布服务层整组命令。N 拍测速需要 N+1 个连续有效位置；失效后重建窗口，期间保留上次速度。仍有部分 Adapter 依赖 `foc_t`，尚未全部拆除。

下一步先让负责人阅读七步主流程和状态选择，再以本轮冻结候选进行硬件状态预检；停机/失能、反馈和 PWM 状态确认干净后，按启动、对齐、已验速度模式、停止逐项验收。后续 VF/IF/三闭环扩展与无感算法另立范围，不在本轮顺带接入。
