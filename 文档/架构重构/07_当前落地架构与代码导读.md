# 当前落地架构与代码导读

## 1. 一句话说明

现在的主链可以理解为：每次 ADC 控制中断到来，先取得这一拍的角度、电流和母线电压，
再由 Drive 判断能不能运行、运行哪一种控制，Control 算出三相占空比，最后由 Target 写入
TIM1。无效模式、无效占空比或达到保护判定条件时，不允许继续沿用上一拍 PWM。
位置反馈允许连续 3 个无效样本的去抖时间，超过后锁存故障并关断输出。

## 2. 当前正式数据流

```text
ADC1 注入转换完成中断（20 kHz）
  -> App / fast_loop_step()
       1. Target Encoder 读取 MT6816 原始角度
       2. Motor Feedback 换算机械角、电角度和多圈位置
       3. Target ADC 读取三相电流和母线原始值
       4. Motor ADC 换算为 A、V 等物理量
       5. 组成 control_cycle_input_t
  -> control_cycle_step()
       6. 更新本周期反馈
       7. Drive 检查反馈、保护、请求、状态和模式
       8. Control 执行电压/电流/速度/位置控制与 SVPWM
       9. Drive 校验占空比、处理相序并记录提交
      10. Target PWM 写 TIM1 CCR1/CCR2/CCR3
  -> 发布同一 fast_seq 的只读调试快照
```

FOC 算出的并不是“立即改变引脚的电压”，而是 0～1 的三相逻辑占空比。Drive 先检查它，
Target 再把比例乘以 TIM1 周期并写入比较寄存器；真正从引脚生效的时刻由 TIM1 的中心对齐、
预装载和更新事件决定，首次上电要用示波器确认。

## 3. 四层职责

| 层 | 负责什么 | 代表文件 |
|---|---|---|
| App | 一拍控制按什么顺序执行、何时放行、调试快照 | `fast_loop.c`、`control_cycle.c` |
| Drive | 启停、故障、模式、命令限幅、功率输出边界 | `drive.c`、`drive_mode.c`、`drive_protection.c` |
| Control | 不依赖 HAL 的 FOC、PID、级联和 SVPWM 计算 | `control_loop.c`、`foc_core.c`、`control_cascade.c` |
| Target | 当前 STM32G474 的 ADC、SPI 编码器、TIM1 PWM | `target_adc.c`、`target_encoder.c`、`target_pwm.c` |

`User/motor` 目前是旧 `pmsm_t` 与新 Control/Target 边界之间的薄适配区。它负责参数初始化、
物理量换算和把当前模式所需字段映射给 Control，不再直接操作 PWM 寄存器。

## 4. 状态机怎么工作

正式状态只有四个：

| 状态 | 大白话含义 |
|---|---|
| `STOP` | 功率输出关闭，等待命令 |
| `STARTING` | 已检查模式并成功启动 PWM，本拍不直接跑控制 |
| `RUN` | 每拍执行选定模式并提交新 PWM |
| `FAULT` | 故障已锁存，关闭 PWM，必须明确清故障后才能重新启动 |

请求路径是：

```text
STOP 请求 -> 保持或关闭 PWM
START 请求 -> 校验模式/命令 -> 先写 50% 中性占空比 -> 启动六路 PWM
下一拍自动变成 RUN 请求 -> 执行选定控制模式
故障或无效模式 -> 关闭 PWM -> 进入 FAULT 或 STOP
```

## 5. 当前允许运行的模式

| 类别 | 已放行模式 |
|---|---|
| 调试 | V/F、I/F、开环电压、电流环、速度—电流环、位置—速度—电流环 |
| 正式 | CST 转矩、CSV 速度、CSP 位置 |
| 停机 | Quick Stop 减速停机 |

MIT、轨迹、辨识、标定、齿槽补偿和无感算法不是被“藏在分支里”，而是已经从正式构建清单移出。
以后某个算法完成纯算法测试和硬件验证后，再单独接回模式表，不影响现有主链。

## 6. 可迁移性来自哪里

- Control 只收显式输入，不读取 ADC、SPI、TIM 或全局硬件寄存器；
- `control_cycle_input_t` 可以来自真机、CSV 回放、仿真模型或 HIL；
- 换 MCU 时主要替换三个 `target_*` 文件，FOC 和状态逻辑不需要跟着改；
- 调试数据使用只读快照，不再让大调试结构体反向参与控制；
- 命令、反馈、占空比和故障都带有明确的有效性边界。

## 7. 当前不做的事情

- 不为了“看起来现代”拆掉整个 `pmsm_t`；
- 不重写已经有数值对照的 FOC 公式；
- 不给每个算法建立插件、注册表或复杂抽象；
- 不猜测未提供的 Gate Fault/Break 引脚；
- 不宣称温度、实时同拍和物理关断延迟已经通过硬件验证。

这保证当前框架足够清楚，又没有为了架构而架构。
