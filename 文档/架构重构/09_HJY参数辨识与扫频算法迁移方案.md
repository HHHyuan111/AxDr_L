# HJY 参数辨识与扫频算法迁移方案

## 一、结论

这份资料可以移植，但只移植 `portable_public` 中的平台无关算法，不移植附件中的整套工程、
板级驱动、参数存储和可执行固件。

本次迁移采用以下原则：

1. 保留 HJY 公开算法的数学公式和状态机，先不做“顺手优化”。
2. 算法不直接读 STM32 寄存器，不直接启停 PWM，也不直接写 Flash。
3. 辨识期间由 Drive 分配唯一控制权，最终仍通过现有 Control 计算和 Drive 提交 PWM。
4. 所有试验电流、电压、频率和时间进入单独参数包，不散落在算法代码中。
5. 第一个上电节点只打通低电流单点扫频；确认数据链正确后，再做完整扫频、Rs、L、极对数和编码器零位。
6. 辨识结果先只显示和导出，不自动覆盖电机参数，也不自动写入 Flash。

这样做不会推翻我们已经搭好的 App、Drive、Control、Target 架构，只是在 Drive 中增加一条受控的
“诊断/辨识运行支路”。正常电流环、速度环、位置环和 MIT 模式保持原样。

## 三、算法用大白话解释

### 3.1 电流扫频

给 d 轴或 q 轴电流指令叠加一个正弦波，例如让目标电流按 100 Hz 上下变化；同时记录实际电流跟得上多少、
落后多少。逐步改变正弦波频率，就能画出电流环的增益和相位曲线，看到电流环带宽和稳定余量。

它使用现有电流 PI，不直接输出 PWM。它输出的是下一周期的 `id_ref`、`iq_ref`。

### 3.2 Rs 辨识

让电机在固定电角度下依次建立几个不同的 d 轴直流电流平台，记录稳定后的电压和电流。根据
`电压差 / 电流差` 求相电阻。使用多个平台做差，可以减小共同死区压降对结果的影响。

它不是调用现有电流 PI，而是在算法内部用一个积分器调 d 轴电压，所以属于受控的电压注入测试。

### 3.3 正偏置 L 辨识

先建立一个正的 d 轴电流，保证电流不跨过零点；再让 d 轴电压在两个值之间快速切换，观察电流上升和下降的
斜率。结合已经辨识出的 Rs，按 `V = R·I + L·dI/dt` 计算相电感。

这个算法依赖可信的 Rs、电流采样和实际施加电压，因此放在 Rs 后面。

### 3.4 极对数和编码器零位

用一个缓慢旋转的开环电角度拉着转子转，比较“电角度转了多少圈”和“编码器机械角转了多少圈”，求极对数和
编码器方向。然后把转子对齐到已知电角度，多次采样编码器，求电角度零偏。

这一步会产生真实机械运动，必须在扫频、Rs、L 和停机流程都验证后再做。

## 四、与当前框架的接口关系

### 4.1 最终快速周期

```text
ADC 中断（20 kHz）
    ↓
Fast Loop 读取本周期编码器和三相电流
    ↓
Drive 判断：普通运行，还是诊断/辨识取得控制权
    ├─ 普通运行 → 原有电流/速度/位置/MIT 控制
    └─ 诊断运行 → 组装 mc_sample → HJY 算法算出下一拍 mc_command
                                      ↓
                         映射为现有电流模式或电压模式
                                      ↓
                         Control 完成 FOC、SVPWM
                                      ↓
                         Drive 统一检查并提交 PWM
                                      ↓
                         Target 写入 TIM1 比较寄存器
```

HJY 核心只看得到物理量和抽象命令，看不到 `pmsm_t`、HAL、TIM1、ADC 和编码器芯片。

### 4.2 当前可直接映射的数据

| HJY 数据 | 当前数据 | 处理方式 |
|---|---|---|
| `ia_a/ib_a/ic_a` | `pm->foc.i_a/i_b/i_c` | 已是安培，直接映射 |
| `i_alpha_a/i_beta_a` | 当前三相电流经 `foc_clarke()` | 每周期用新 ADC 样本现算，不能使用上一拍旧值 |
| `theta_elec_rad` | `pm->foc.p_e` | 已是电角度弧度，直接映射 |
| `theta_mech_rad` | `pm->foc.mp_r` | 已是机械角弧度，直接映射 |
| `omega_mech_rad_s` | `pm->foc.wr_f` | 直接映射 |
| `vbus_v` | `pm->foc.vbus` | 已是伏特，直接映射 |
| `encoder_raw` | `pm->pos_box.raw_1` | MA732 原始计数，满量程使用实际 CPR |
| `vd_v/vq_v` | 上一拍实际控制命令 `pm->foc.v_d/v_q` | 用于 L 辨识，必须与当前样本时序对应 |
| `fault_code` | `pm->fault.all` | 任一 Drive 故障立即终止辨识 |
| `voltage_saturated` | 当前框架尚无正式字段 | 迁移时补一个明确的调制/电压限幅结果 |

### 4.3 电流和 PI 参数必须特别处理

本项目电流换算为：

```text
相电流[A] = (ADC 原始计数 - 零偏计数) × pm->board.i_ratio
```

所以 HJY 算法的所有电流参数也必须使用“相电流安培”，不能填 ADC 计数，不能填母线电流。

HJY `mc_current_pi` 给出的 `Ki` 是“每个控制周期的积分增量”；当前项目
`control_pid_parallel_step()` 内部还会再乘一次 `ts`。因此应用参数时必须转换：

```text
本项目 Ki[每秒] = HJY Ki[每拍] / Ts
```

或者直接在本项目按以下连续域公式计算：

```text
wc = 2π × bandwidth_hz
Kp_d = Ld × wc
Kp_q = Lq × wc
Ki_d = Ki_q = Rs × wc
```

绝不能把附件的每拍 `Ki` 原值直接写入 `pm->id_pi.ki` 或 `pm->iq_pi.ki`。

当前参数中 `Ld/Lq` 约为 20 μH，而 `Ls` 约为 0.2 μH，差约 100 倍；现有电流 PI 使用的是 `Ls`。
在参数来源和相值/线值含义确认前，不修改这个参数，只把它列为辨识结果对照项。

## 五、建议的代码组织

不新建第二套 FOC，也不新开代码库。继续在当前仓库渐进迁移：

```text
User/
├─ diagnostic/
│  ├─ core/                 HJY 公开纯算法，首轮保持公式不变
│  ├─ diag_runner.c/.h      选择一个任务并维护任务状态
│  └─ diag_profile.c/.h     本电机测试电流、电压、频率和时间参数
├─ drive/
│  └─ drive_diag.c/.h       pmsm_t 与 mc_sample/mc_command 的唯一适配处
├─ control/                 继续使用现有 FOC、PI、坐标变换和 SVPWM
├─ bsp/                     继续使用现有 ADC、编码器和 PWM Target
└─ app/                     继续使用现有 20 kHz Fast Loop
```

只增加三个概念：

1. `diag_job`：要做哪项试验，例如 D 轴扫频、Rs 或 L；
2. `diag_state`：空闲、准备、运行、停机、完成、失败；
3. `diag_result`：当前进度和结果，供调试器读取。

不增加消息总线、插件系统、动态注册、RTOS 任务和动态内存。

## 六、控制权和停机流程

辨识不是普通的 `id_set/iq_set` 改值，它会临时改变控制模式，所以同一时间只能有一个任务控制电机。

```text
IDLE
  ↓ 收到任务请求，且 Drive 已 STOP、PWM 已关闭
PREPARE
  ↓ 参数检查通过，清空本次算法状态
STARTING
  ↓ Drive 按现有流程开启 PWM
RUNNING
  ↓ 每个 50 μs 周期执行 sample → algorithm → command → FOC → PWM
STOPPING
  ↓ 指令归零，向 Drive 请求 STOP
DONE / FAILED
  ↓ 确认 PWM 已关闭后释放控制权
IDLE
```

任何 Drive 故障、用户停止、无效占空比或算法失败，都走同一个 `STOPPING`，不允许算法直接重新使能，
也不自动清除故障。

## 八、今天下午的测试范围

今天不建议直接跑完整 Rs、L 和极对数流程。第一轮上电只验证“适配是否接对”。

### 8.1 上午开发完成条件

- 完成节点 1、节点 2 和节点 3 的单点扫频；
- 正常模式默认行为不变，诊断默认不启动；
- 可以在调试器中看到 `job/state/fault/frequency/id_ref/iq_ref/id/iq/vd/vq/vbus/saturated`；
- 能通过调试变量发出开始和停止请求；
- 固件 Debug/Release 零错误零警告，全部 Host 测试通过。

### 8.2 上电前必须明确的实物参数

当前代码里的电机 `rated_current` 和 `peak_current` 均为 0，80 A 只是现有软件过流阈值，不能作为安全试验电流。
下午通电前必须从电机资料或同事处确认：

1. 电机允许的连续相电流和短时峰值相电流；
2. 当前母线电压和电源限流值；
3. 试验时转子是允许自由转动还是需要固定；
4. 编码器 CPR、方向和当前零位是否已经做过实物确认。

在这些值确认前，`diag_profile.safe_current_limit_a` 默认保持 0，算法拒绝启动。确认后再填写一个明确的测试上限，
所有扫频偏置和幅值必须满足：

```text
abs(offset_a) + abs(amplitude_a) <= safe_current_limit_a
```

### 8.3 下午第一轮上电顺序

1. 功率未使能：观察三相电流零点、母线电压和编码器角度是否合理。
2. 现有普通零电流闭环：START 后保持 `id_ref = 0`、`iq_ref = 0`，确认可随时 STOP。
3. 小 d 轴直流阶跃：只验证正负号、相序和电流单位；电流异常立即停止。
4. D 轴 100 Hz 单点扫频：零偏置、小幅值，观察指令和实际电流波形。
5. 手动停止单点扫频：确认下一个快速周期进入停机流程，PWM 关闭。
6. 若前五项正常，再做少量 D 轴多点扫频；首日不直接跑 20 Hz～2000 Hz 的 128 点全量测试。
7. D 轴稳定后再做 Q 轴单点；若转子产生明显转矩或机械运动，停止并重新确定试验约束。

第一轮验收只回答四个问题：

- 电流安培单位和正负号对不对；
- 算法使用的是当拍反馈、输出的是下一拍命令，时序对不对；
- D/Q 轴映射对不对；
- STOP 和故障能不能统一关断。

这些通过后，下一次再扩大频点、做 Rs 和 L，不用在第一天下午把所有辨识一次跑完。
