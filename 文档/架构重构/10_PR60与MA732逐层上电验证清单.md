# PR60 与 MA732 逐层上电验证清单

## 一、怎么使用这份清单

今晚上电不追求一次把所有算法跑完，而是从底层往上逐层确认。当前一层没通过，就停在这一层修改；
通过后记录现象并提交一次 Git，再进入下一层。这样出现问题时，能马上知道问题属于采样、编码器、PWM、
电流环，还是上层算法。

每个节点统一执行四件事：

1. 先说明本节点只验证什么，不顺手改其他模块；
2. 观察指定变量和示波器波形；
3. 按通过条件判断，不能只凭“电机转了”判断；
4. 通过后提交，提交信息使用本清单给出的建议名称。

## 二、上电前只确认四个实物值

以下四项必须使用 PR60、电源和当前驱动板的真实数据，不能从旧电机或附件工程照抄：

| 参数 | 填写位置 | 当前处理 |
|---|---|---|
| 允许试验相电流 | `g_diag.profile.current_limit_a` | 默认 0，填入前诊断任务不能启动 |
| 允许试验电压矢量 | `g_diag.profile.voltage_limit_v` | 默认 0，填入前诊断任务不能启动 |
| 实际母线电压与电源限流 | 实验记录 | 先低压、限流验证 |
| MA732 方向、CPR | `pm.pos_box.ma732.dir/cpr` | 当前基线为方向 `+1`、CPR `16384`，需要实物确认 |

诊断电流和电压上限是本次试验上限，不是电机峰值，也不是软件过流保护值。

## 三、逐层验证顺序

### 节点 0：离线基线

目标：证明当前代码在不接电机时是一份可构建、可回退的基线。

操作：

```powershell
./tools/verify_release_candidate.ps1
```

通过条件：

- Host 测试全部通过；
- CMake 与 Keil 的 User 源文件清单一致；
- Debug、Release 均为 0 个错误、0 个警告；
- `git status` 中没有不明来源的修改。

建议提交：`test: 建立PR60与MA732上电前基线`

### 节点 1：板级供电、时钟和调试连接

目标：只确认 MCU、调试器和快速周期在运行，不打开功率输出。

操作：保持 `pm.req = DRIVE_REQ_STOP`，运行程序并观察 `pm.fast_seq` 和 `g_debug_snapshot.seq`。

通过条件：

- 两个周期序号持续增加；
- `pm.state == DRIVE_STATE_STOP`；
- `pm.pwm_active == false`；
- `pm.fault.all == 0`，或故障原因与尚未接入的实物一致且能够解释。

建议提交：`test: 验证板级启动与快速周期`

### 节点 2：ADC 原始值和零电流

目标：确认 ADC 通道、DMA/注入通道、相序映射和安培换算没有接错。

主要观察：

- 原始计数：`pm.adc.ia/ib/ic/vbus`；
- 物理量：`pm.foc.i_a/i_b/i_c/vbus`；
- 有效标记：`pm.fb_status.i_valid/vbus_valid`。

操作：

1. PWM 始终关闭，记录三相零电流原始计数；
2. 核对三相零点是否靠近各自标定零偏；
3. 用已知方向的小电流或受控注入分别检查 A/B/C 相通道；
4. 核对 `i_a + i_b + i_c` 在允许误差内接近 0。

通过条件：三相名称、正负号和安培比例都能逐项解释，静态噪声没有明显跳变或削顶。

建议提交：`test: 验证三相电流与母线采样`

### 节点 3：MA732 原始角度和方向

目标：确认 SPI 读取、14 位数据提取、跨零处理和机械角方向。

主要观察：

- `pm.pos_box.raw_1`：应在 `0..16383`；
- `pm.pos_box.ma732.raw/pos/rev_flag`；
- `pm.foc.e_pr/mp_r/p_e`；
- `pm.fb_status.pos_valid`。

操作：功率输出关闭，手动缓慢正转、反转电机轴，并让编码器跨过一次零点。

通过条件：

- 原始计数连续变化，跨零时累计机械角不突跳一整圈；
- 正转和反转的角度符号与约定一致；
- 转子转一机械圈，原始计数恰好走一圈；
- `p_e` 每机械圈重复 PR60 极对数对应的次数。

本节点只确认“读得对不对”，不修改电角度零偏。

建议提交：`test: 验证MA732角度与方向`

### 节点 4：PWM 启停和三相通道

目标：确认 Drive 的 START/STOP、50% 中性值、三相映射和故障关断。

操作：先断开或限制功率条件，用示波器观察 TIM1 三相主输出和互补输出；执行一次 START，再立即 STOP。

主要观察：

- `pm.req/state/pwm_active`；
- `pm.pwm_cmd` 和 `pm.pwm_commit`；
- `g_debug_snapshot.duty_cmd_a/b/c`；
- 三相门极波形、死区和互补关系。

通过条件：

- START 先提交 50% 中性值，再打开输出；
- ABC/ACB 相序与实物接线一致；
- STOP 后六路输出关闭；
- 制造一个可控的反馈故障时，同一快速周期进入 FAULT 并关断。

建议提交：`test: 验证PWM启停与三相映射`

### 节点 5：开环小电压和电流方向

目标：在闭环前确认电角度、相序、电压方向和电流方向形成同一套约定。

操作：使用 `debug_mode + volt_op`，从 0 开始给很小的 d 轴电压；保持 q 轴为 0，短时间运行后停止。

通过条件：

- d 轴电流方向与 d 轴电压方向一致；
- 三相电流波形和占空比变化能够对应；
- 无异常机械冲击；
- STOP 随时有效。

如果本节点不对，优先检查相序、电流正负号和电角度，不调整 PI。

建议提交：`test: 验证开环电压与电流方向`

### 节点 6：d/q 电流环

目标：证明现有电流 PI、FOC 和 SVPWM 能稳定跟踪 PR60 的电流给定。

顺序：

1. `id_ref = 0, iq_ref = 0` 启动；
2. 小 d 轴正阶跃、回零、小 d 轴负阶跃；
3. d 轴通过后，再做小 q 轴阶跃；
4. 记录给定、反馈、`vd/vq` 和是否饱和。

主要观察：`pm.ctrl.id_set/iq_set`、`pm.foc.i_d/i_q/v_d/v_q` 和三相电流。

通过条件：

- 反馈方向正确，稳态误差和超调在约定范围内；
- d 轴给定主要改变 `i_d`，q 轴给定主要改变 `i_q`；
- 没有持续电压饱和和高频振荡；
- 三次重复结果一致。

本节点通过前，不进入速度环、位置环和任何辨识。

建议提交：`test: 验证PR60电流环`

### 节点 7：速度反馈和速度环

目标：确认 MA732 角度差分得到的速度可信，再闭合速度环。

操作：先在电流环下低速转动，核对 `pm.foc.wr/wr_f`；再使用小速度给定做正转、回零、反转。

通过条件：

- 速度正负号与机械方向一致；
- 低速时无明显跨零尖峰；
- 速度环输出的 `iq_ref` 受明确电流限幅；
- 加减速过程中电流和速度没有持续振荡。

建议提交：`test: 验证PR60速度反馈与速度环`

### 节点 8：位置环和运行模式

目标：确认位置、速度、电流三级级联，以及 debug/release 模式分派。

操作：先做很小的相对位置阶跃，再分别验证位置、速度、电流模式的 START、RUN、STOP。

通过条件：

- 位置目标方向正确，停止后不继续积分或沿用旧占空比；
- 位置环输出受速度限制，速度环输出受电流限制；
- 模式切换只在 STOP 状态进行；
- 未接入的模式明确拒绝启动。

建议提交：`test: 验证位置环与运行模式`

### 节点 9：D/Q 电流单点扫频

目标：先验证新迁移算法的采样时序和命令方向，不立即做全频段扫频。

上电前设置：

- `g_diag.profile.current_limit_a` 和 `voltage_limit_v`；
- `g_diag.profile.sweep.axis`；
- `single_point = true`；
- `single_frequency_hz = 100`；
- `amplitude_a` 从已验证的小电流开始，`offset_a = 0`。

启动：

1. 设置 `g_diag.requested_job = DIAG_JOB_CURRENT_SWEEP`；
2. 设置 `g_diag.request = DIAG_REQUEST_START`；
3. 停止时设置 `g_diag.request = DIAG_REQUEST_STOP`。

观察：`g_debug_snapshot.diag_*`、`g_diag.sweep.result`、`id/iq`、`vd/vq` 和电压饱和标记。

通过条件：

- 指令频率为 100 Hz，反馈频率一致；
- D/Q 轴映射正确；
- 手动 STOP 后 PWM 关闭且诊断控制权释放；
- 结果点的增益和相位可重复，饱和点被明确标记。

D 轴通过后再做 Q 轴；单点通过后再减少频点做小范围多点扫频。

建议提交：`test: 验证DQ轴电流扫频`

### 节点 10：Rs 和正偏置 L 辨识

目标：先求相电阻，再把确认后的 Rs 用于电感辨识。

顺序：

1. 设置 `DIAG_JOB_RS_IDENT`，填写小电流 `current_min_a/current_max_a`；
2. 重复三次，对比 `g_diag.rs.result.phase_resistance_ohm`；
3. 人工确认 Rs 后更新 `g_diag.profile.phase_resistance_ohm`；
4. 设置 `DIAG_JOB_L_IDENT`，执行正偏置电感辨识；
5. 对比 `g_diag.inductance.result.phase_inductance_h` 与已有 PR60 参数。

通过条件：结果有效、无电压限幅、三次结果集中，并能说明相值/线值的换算关系。

结果只记录，不自动覆盖 `pm.para`，不写 Flash。

建议提交：`test: 验证PR60电阻与电感辨识`

### 节点 11：极对数、MA732 方向和电角度零位

目标：用真实机械运动验证 PR60 极对数、编码器方向和零位。

顺序：

1. 保证转子可以自由、缓慢转动；
2. 设置小的 `pole_pair.drive_current_a`，运行 `DIAG_JOB_POLE_PAIR_IDENT`；
3. 检查未取整极对数是否接近整数，方向是否与节点 3 一致；
4. 人工确认极对数后，设置小的 `encoder_align.align_current_a`；
5. 运行 `DIAG_JOB_ENCODER_ALIGN`，重复三次比较零位结果。

通过条件：极对数重复一致，零位结果集中，过程无卡滞和异常电流。

结果仍不自动写入正式电机参数。确认后由我们一起修改 PR60 参数并单独提交。

建议提交：`test: 验证PR60极对数与MA732零位`

### 节点 12：PI、偏置带宽和其余迁移算法

目标：在基础控制和辨识结果可信后，再评估算法增强项。

顺序：

1. 使用确认后的 Rs/L 和目标带宽调用 `diag_current_pi_for_project()`；
2. 新 PI 先离线对比，再做小电流阶跃和扫频；
3. 多个偏置电流的扫频结果交给 `mc_bias_bandwidth_build()`；
4. 磁链估计只做只读观察，不参与角度闭环；
5. 死区测试通过后才评估死区补偿；
6. 解耦默认保持 `MC_DECOUPLING_NONE`，高速电流环数据证明需要时再启用。

通过条件：每个增强项都有“启用前/启用后”同工况对照，不能只看主观感觉。

建议提交按功能拆分，不把 PI、磁链、死区和解耦混在一次提交中。

## 四、出现问题时按哪一层查

| 现象 | 优先检查层级 |
|---|---|
| 三相电流名称或正负号不对 | 节点 2：ADC 和相序映射 |
| 电角度跳变、速度尖峰 | 节点 3：MA732 与跨零 |
| 占空比正确但门极不对 | 节点 4：PWM/Target |
| 开环方向不对 | 节点 2、3、5，不先调 PI |
| 电流环振荡 | 节点 6：单位、角度、PI、采样时序 |
| 速度环振荡 | 先确认节点 6，再看节点 7 |
| 扫频结果离谱 | 节点 6、9：电流环、当拍采样、饱和 |
| Rs/L 重复性差 | 节点 2、4、10：零偏、死区、温升和电压限幅 |
| 极对数或零位不稳定 | 节点 3、6、11：编码器、力矩和机械卡滞 |

## 五、最终完成标准

算法“代码已经迁移”只代表离线阶段完成；整个任务完成必须同时满足：

- 节点 0 到节点 8 的基础平台逐层通过；
- 扫频、Rs、L、极对数和 MA732 零位均完成实物重复验证；
- 每个结果都有试验参数、原始记录和通过结论；
- 正常模式与诊断模式都能统一 STOP、统一故障关断；
- 所有确认后的参数变更单独提交，可追溯、可回退；
- Debug/Release 和全部 Host 测试仍保持通过。
