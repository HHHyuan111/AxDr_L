# 11 扩展点与落位规则

> 冻结文档。回答"新增代码放哪、要动几个现有文件"。配套：目标架构图（三层视图）。

## 1. 框架 = 八个插槽

每个插槽 = 一个稳定接口 + 一个集中注册/选择点。新代码只允许通过插槽进入框架。

| # | 插槽 | 接口位置 | 注册/选择方式 |
|---|---|---|---|
| ① | 控制器 | 电流/速度/位置环接口（输入给定+反馈，输出电压） | 配置选择字段 + 一处集中 switch/函数表 |
| ② | 传感器 | sensor 接口（实现 read_raw，接口层统一算速度/多圈） | 装配清单实例化 + 仲裁器选择 |
| ③ | 命令源 | 门面 API（request_state / set_target / param_get_set） | 协议命令表 / 按键映射表 |
| ④ | 配置 | motor_cfg_t 结构 + 默认档案 + flash 存储 | 版本号 + CRC，读败回默认 |
| ⑤ | 保护 | 保护检查函数 + 错误位图（mot_err_e） | 保护表中登记，常驻不可旁路 |
| ⑥ | 遥测 | debug_snapshot 只读快照字段表 + VOFA 帧表 | 字段表加一行 |
| ⑦ | 模式 | 模式表（每拍放行判定） | 模式表加项 |
| ⑧ | 板级 | target 七模块函数族 | 每板一份实现 |

## 2. 扩展场景落位表（每行 = 加东西时的标准答案）

| 扩展场景 | 要动 | 绝不动 | 插槽 |
|---|---|---|---|
| 电流环加 ADRC | 算法库(核)+控制层(壳)+配置 | 级联/Drive/Target/协议 | ①④ |
| 新增无感算法 | 算法库(核)+适配层(传感器包装)+装配 | 控制层全部 | ②（HFI 类另需 inject 钩子，已预留） |
| 换/加编码器 | 适配层新实现+装配一行 | 上层全部 | ② |
| 上位机新按钮 | 协议命令表一行（调既有门面） | 内部全部 | ③ |
| 换电机 | 配置新档案 | 全部代码 | ④ |
| 新增保护项 | 保护函数+错误位+阈值进配置 | 状态机框架 | ⑤④ |
| 加观测曲线 | 快照字段+VOFA 帧各一行 | 控制链路 | ⑥ |
| 加通信总线 | 服务层新协议+Target 加外设 | 控制/驱动域 | ③⑧ |
| 加控制模式 | 模式表加项+控制编排函数 | 状态机本身 | ⑦ |
| 换 MCU 板 | Target 7 文件+装配 | 上层全部 | ⑧ |

三问模板：算法核放哪？（→算法库）谁每拍调它？（→控制层壳或传感器包装）用户怎么选它？（→配置/装配/命令表，只能选一处）。

## 3. 反向纪律

任何新代码若发现自己要同时改 **两个以上插槽** 才能落地 = 在破坏架构，停下来先讨论接口。

## 3b. 唯一顶层单例的合法性说明

03 号规范规定"不新增可写全局单例"。本框架唯一允许的例外：电机实例（单电机项目，
类型名按 12 号命名决策不带框架前缀）——它是显式上下文聚合体，每个字段有唯一写者
（见架构图与 07 号数据流），属于 03 号"跨模块共享对象只有一个创建者和写者"的合规形态。
除此之外一切可变状态必须进结构体上下文，禁止新增散装全局变量。

## 4. 明确排除项（个人项目，不量产）

双电机、固件远程升级（IAP）、EtherCAT——不做，接口也不预留。将来真需要，届时再议。

## 5. 遗留待办（框架搭建时补齐为显式任务）

- 控制器插槽：电流环调用点必须收敛为单接口（当前若为硬编码 switch 需重构）
- 协议命令表：统一注册机制
- HFI 注入钩子：sensor 接口预留可选 inject 函数
