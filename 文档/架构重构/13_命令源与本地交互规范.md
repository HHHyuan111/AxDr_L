# 13 命令源与本地交互规范

> 冻结文档。回答"上位机按钮、按键、旋钮这类交互怎么加"。

## 1. 命令源平等原则

上位机（USB/串口）、板载按键、旋钮电位器都是**命令源**，地位完全平等。
唯一规则：**只提请求 → 经门面 API → 状态机/模式表校验**。任何命令源：

- 不得直接写内部结构体字段
- 不得绕过门面调用控制层函数
- 请求被拒（状态不允许/参数越界）必须得到明确返回码并可查询

## 2. 按键方案（板上 PC6/PC7/PC8/PC9，target 已可读）

- service 层新增 `input_task`（主循环，1ms 周期）：扫描 → 消抖 → 事件识别（短按/长按/连发）
- 事件经**映射表**翻译成门面调用；映射表进配置：

```c
typedef struct {
    uint8_t  key;        /* 1..4 */
    uint8_t  event;      /* 短按/长按/连发 */
    uint8_t  action;     /* ACTION_START / ACTION_STOP / ACTION_NEXT_MODE / ACTION_CLR_FAULT ... */
} keymap_entry_t;
```

- 新增一个按键功能 = 映射表加一行，不改任何现有代码。

## 3. 旋钮方案（ADC 空闲通道，如 PC4——板上是否焊电位器待确认）

- target 已有 ADC 规则组 DMA；读数 0..4095 → 百分比 0~100%（带死区与反向配置）
- 百分比映射到**当前模式的限幅内目标**：速度模式 = N% × pmax_vel；力矩模式 = N% × pmax_iq
- 经 `set_target()` 提给门面；映射对象（控制哪个量）进配置
- 安全三防线均为现成机制：模式表放行判定 / 状态机请求校验 / 目标限幅

## 4. 上位机命令

- 新按钮 = 协议命令表注册一行（命令 ID → 门面调用），协议层只认识门面不认识内部结构
- 若按钮需要的固件能力尚不存在（如"导入参数包"）：先在门面加 API，再接按钮，顺序不可反
- 命令表带版本号；上位机与固件协议版本不匹配必须显式报错

## 5. 与既有资产的关系

沉沙ABZ 固件的 contract 层（command/telemetry/scope/hmi contract）是本规范的超集雏形，
迁移时其协议格式与上位机连通性作为行为基准，命令注册机制按本规范收敛。
