# 15 资源与栈规范

> 冻结文档。目标：算法开发者只背 R1 六条，其余机器查/上板测。
> 实测数据与预算依据见《AxDr资源占用报告与预算.md》（工作区），复测脚本
> scripts/build_measure.sh。

## 1. 资源清单与已知现状（dev@6e012f4 实测）

| 资源 | 上限 | 实测 | 风险点 |
|---|---:|---:|---|
| Flash | 512 KB | 87.2 KB (16.6%) | 字体表 13.3KB、USB ~8KB、libm 1.6KB |
| SRAM（不含栈） | 128 KB | 31.7 KB (24.2%) | g_diag 8.4KB、USB 缓冲 4KB、RamFunc 代码 ~6.5KB |

SRAM 布局注：128KB = SRAM1(96K)+SRAM2(32K) 连续（0x20000000 起，DMA 均可达）；
另有 10KB CCM-SRAM（0x10000000）**DMA 不可达**，当前未用——跨系列移植时此条必须重查。
| RT 时间片 | 8,000 周期/拍 | 未测 | 无测量手段前不许堆 RT 计算 |
| 栈 | 冻结提案 8 KB | 现仅 0x400 检查 | 溢出症状=玄学 HardFault，必须水位验证 |
| 堆 | 冻结提案 0 | 现 0x200 且 mem.0 已被链入 | printf 家族隐式 malloc |

## 2. R1 编码禁忌（算法开发者唯一要背的 6 条）

1. RT 上下文（20kHz 管线）禁：malloc、printf、递归、无界循环、flash 写、LCD、SPI 长传输
2. 局部数组 >64 字节一律改 static 或入结构体（局部大数组是栈爆头号来源）
3. 缓冲/表的大小必须来自配置常量并过预算表（防 .bss 黑洞——旧固件 pm 曾白占 ~45KB）
4. 大表（LUT/齿槽/字体）挂编译开关，不用即 0
5. 新函数进 RT 链前跑一次 ISR 耗时测量（DWT，10 秒的事）
6. 链接脚本/栈/堆不擅自改，走 review

## 3. R2 机器自动查（不靠人记）

- `-fstack-usage` 生成 .su → 脚本算最深调用链 vs 栈大小
- 链接断言：堆 = 0
- map 报告每模块 RAM/Flash vs 预算表（check.sh 输出）
- grep `malloc|printf|calloc` 出现在 control/ drive/ 即报错

## 4. R3 上板体检（每次硬件冒烟，10 分钟，三项进 debug_snapshot 常驻字段）

- 栈水位：启动填 0xA5 油漆，运行后读最大浸没 → 快照字段 `stack_hwm`
- ISR 耗时：DWT->CYCCNT 包住 RT 管线记 min/max → 快照字段
- CPU 负载 = ISR 周期 ÷ 8000 → 快照字段

## 5. 一次性审核表（冻结时定死，此后不碰）

| 项 | 现状 | 定为 | 理由 |
|---|---|---|---|
| 堆 | 0x200 | **0** | 无 malloc；禁 printf 家族（VOFA 自序列化不受影响） |
| 栈 | 0x400 | **8 KB** | HAL 深链一条可吃 1KB+；水位实测后可回调 |
| NVIC 优先级 | 全 (0,0) | RT 最高→MID 次之→其余让路 | 全最高=无抢占控制、临界区失效 |
| DMA 通道 | 无表 | 分配表一张 | 新增外设先查表 |
| RamFunc | ~6.5KB | 只保留 ISR 主链热点 | 非热函数移出 |
| 大表开关 | 无 | AXDR_USE_LCD / USB / DIAG | 不用即 0 |

## 6. 移植注意

跨系列换板时查参考手册确认 DMA 对各 RAM 区可达性（F4 的 CCM DMA 不可达；G474 的
128KB 连续无此问题）。DMA 缓冲位置写进板级移植清单。

## 7. 与旧固件（沉沙ABZ）的关系

旧固件"资源满"的直接原因即本规范的反面清单（无预算、大表常驻、栈未验证、堆未清零）。
迁移到新框架后预算表强制生效；迁移期间每步跑 build_measure.sh 对比，资源曲线不允许
单调上涨。
