## 第一章 这个系统本质上是什么

一块 STM32G474 板子，通过 6 个 MOS 管给电机三相绕组通电流，让转子转到想要的位置/速度/力矩。
整个固件只回答一个问题：

> **每个 50 微秒（20kHz），三相 PWM 的占空比应该是多少？**

架构的一切设计都围绕这条 50µs 流水线：怎么知道转子在哪（采样与传感）、该输出多少电压
（算法与控制）、凭什么允许输出（状态机与保护）、以及怎么让这些代码在换板/换电机/换算法时
不用重写（分层与契约）。

## 第二章 静态视角：三个大层、九个模块

## 第三章 动态视角：一拍的完整旅程

每个 50µs，ADC 注入转换完成中断触发，固定管线顺序执行。
**管线顺序 = 数据依赖顺序**——这是替代一切锁的规则：

```
①target层   ADC注入中断 → 读原始计数：三相电流(PA0/1/2)+母线电压(PC5)
      ↓ 原始计数
②device层   换算：计数→安培/伏特（增益 1mΩ·20×、分压21× 在这里）
            sensor->read_raw() 读编码器 → 接口层统一算角度/速度/多圈
      ↓ 物理量(SI单位：A/V/rad)
③control层  Clarke→Park → 电流环PI →（速度环PI→位置环P，按模式）
            输出 vd/vq（伏特！不是占空比）
      ↓ vd/vq + 使能请求
④drive层    审查：输出合法吗？（占空比≤限幅？状态允许输出？保护没跳？）
            通过 → 伏特→占空比(0~1) + 相序映射 → 生成"收据"
            不通过 → 否决，强制安全占空比
      ↓ 占空比请求+收据
⑤target层   执行：占空比 × TIM1周期(ARR=4000) → 写 CCR1/2/3
   中断退出。50µs 后再来一遍。
```

三个关键设计决策：

1. **③ 只产出"逻辑意愿"，⑤ 只执行"物理动作"，④ 介于其间握否决权。**
   控制算法再疯（PI 失控输出 999V），Drive 层一眼看穿并否决。
   这就是保护"不可旁路"的原因——它不在控制算法的信任链里。
2. **每字段每周期只有一个写者**。①写原始值、②写物理量、③写 vd/vq、④写占空比、⑤执行。
   永远不需要问"这个变量谁改的"——答案写在字段注释里。
3. **为什么没有竞态**：整条链在同一个中断里顺序执行，后级读到的前级数据必然是本周期刚算的。
   唯一跨上下文通路是主循环写 `target`（指令），走 <1µs 临界区。

## 第四章 慢速世界：主循环在干什么

主循环（每圈一次）是慢速世界中枢：

1. 收命令：上位机（USART3/USB CDC）+ 按键 + 旋钮——三者是**平等命令源**，
   都只调门面 API（`mot_request_state()` / `mot_set_target()`）
2. 跑状态迁移：状态机在这里切换（**ISR 永不改状态**，中断里只读状态选分支）
3. 发布快照：打包只读 `debug_snapshot` 给 VOFA/上位机/显示
4. 资源健康：ISR 耗时、栈水位、CPU 负载（15号规范 R3 三个常驻字段）

## 第五章 状态机：四个状态，每个都有"为什么"

```
STOP ──START请求(校验模式+命令)──→ STARTING ──下一拍自动──→ RUN
 ↑│                                    │首拍故障(虚线)        │
 │└──────── 显式清除故障 ←── FAULT ←───保护触发/占空比越限/丢编3拍┘
 └──────────── STOP请求 → Quick Stop 减速停机 ←──────────────┘
```

- **STOP**：功率关闭。上电默认——**默认安全**原则
- **STARTING**：首拍先写 50% 中性占空比再开 PWM。因为上管刚开的第一个周期电流采样
  尚未建立，直接跑闭环等于盲飞
- **RUN**：每拍执行模式表放行的模式（调试 6 种 / 正式 CST·CSV·CSP）
- **FAULT**：锁存。必须显式清除——防止故障原因没查清就重启

模式表与状态机分离：加新模式 = 模式表加一行（插槽⑦），状态机一字不动。

## 第六章 契约：模块之间只传"结构化数据"

| 契约 | 谁写 | 谁读 | 内容 |
|---|---|---|---|
| `control_cycle_input_t` | app 采样链 | control_cycle | 一拍全部输入——**回放缝**：可来自真机、CSV回放、仿真 |
| `duty 请求+收据` | Control 请求 / Drive 收据 | Target | 逻辑占空比、限幅结果、拒绝原因 |
| `motor_cfg_t` | 上电 flash 读 / 门面写 | 所有层 | 电机档案+环路增益+限幅——**类型在各自算法 .h，值集中在此** |
| `debug_snapshot` | app | service | 只读调试快照（协议层只能看这个） |

**"以数据为缝"是回放测试的根基**：`test_control_replay` 用录波数据喂
`control_cycle_input_t` 离线复现整条控制链。调算法不烧板，造输入数据即可。

## 第七章 八个插槽：加东西的唯一入口

详表见 11 号规范。心智模型：

- **加 ADRC**：算法核进 algorithm/（纯数学+单测）→ 控制层加壳实现电流环接口 →
  配置加选择字段。三个插槽各加各的，级联/Drive/Target 零改动
- **加无感**：观测器核进 algorithm/ → 包装成传感器进 device/ → 仲裁器选它。
  控制层不知道角度哪来的
- **上位机加按钮**：命令表加一行调门面。协议永远不认识内部结构体

反向纪律：新代码要同时动两个以上插槽 = 设计有问题，停下来讨论。

## 第八章 规矩挂在架构哪些点上

- **数值政策（14号）**：全局 float SI。标幺化只在两处：SVPWM 内部（伏特→占空比需除
  vbus）和限幅表。写算法永远用物理单位，不操心基准值
- **资源规则（15号）**：R1 六条禁忌管写法（RT 内禁 malloc/printf、局部数组≤64B）；
  R2 机器查（栈深/堆0/map预算）；R3 三个健康数字常驻快照（ISR耗时/栈水位/CPU负载）
- **并发规则**：单写者字段 + 32位对齐原子读 + 命令写入走临界区。没有锁、没有线程

## 第十章 预答疑问

**Q：为什么 Control 输出伏特不是占空比？**
伏特是物理量，算法只需知道"加多大电压"；占空比取决于母线电压（会变）。
换算关在 Drive/Target 边界，算法层永远见不到 `1/vbus`。

**Q：有了状态机为什么还要模式表？**
状态机管"能不能动"（功率维度），模式表管"怎么动"（控制维度）。
标定/辨识将来作为独立状态接入，不污染模式表。

**Q：删掉的 vofa.c/w25q16.c 可惜吗？**
功能和代码是两回事。功能在 P7 都会有，按新契约重写。旧代码在 git 历史（6e012f4）随时可查。

**Q：pmsm_t（pm 全局结构体）去哪了？**
拆成四块：配置进 `motor_cfg_t`（可持久化）、测量进 `meas`（管线生产）、
目标进 `target`（只有门面能写）、环路状态进 `loop`（只有 cascade 任务能写）。
拆开原因：旧 pm 谁都能写；新四块每个字段有唯一写者。
