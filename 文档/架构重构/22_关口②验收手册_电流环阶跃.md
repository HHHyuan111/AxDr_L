# 22 关口②验收手册——沉沙电机电流环阶跃（新架构首次驱动电机）

> P5 产物上机验收指南。固件要求：本提交（P5）之后构建。
> 本手册同时是安全操作规程——**新架构第一次给电机通电**，逐条执行，不跳步。

## 0. 本次验收验证什么

| 项 | 内容 |
|---|---|
| 沉沙档案装载 | Rs/L/flux/pn/ibw=4000 等全部进入运行时（主机测试已锁，上机复核关键项） |
| 电流零偏 | 上电静止零偏采集有效（静态电流读数 ≈0） |
| **电流环阶跃** | d 轴电流阶跃跟随：快、准、稳（与 B 库同参数在沉沙上的行为对照） |
| 保护常驻 | 指令限幅 ±8A、过流 10A 生效（不主动触发，验证装载即可） |

## 1. 安全前提（不可跳过）

1. **电源**：24V 供电（B 库台架区间 10~30V），**限流 5A** 起步
2. **电机轴空载自由**，附近无工具线缆（首次通电可能意外转动）
3. **主要用 d 轴阶跃**（不产生转矩，转子静止）；**iq 阶跃会使电机转动**——转子必须固定或预期转动方向清空
4. 首个阶跃只用 **±1A**（额定 11.5A 的 9%），确认正常再试 2A/4A
5. 异响/异动/电流异常 → 立即 `g_foc.req = 0`（STOP）

## 2. 烧录与连接

- Keil Rebuild + Download（或 gcc 产物烧录）；J-Link 连接
- J-Scope 载入 `MDK-ARM\AxDr\AxDr.axf`（uint32 字段加不了用 Keil Watch，关口①经验）

## 3. 观察变量表（Keil Watch，勾 Periodic Window Update）

| 变量 | 看什么 |
|---|---|
| `g_foc.state` | 0=STOP 1=STARTING 2=RUN 3=FAULT（确认状态机） |
| `g_foc.fb.i_d` / `i_q` | 实际 d/q 电流 [A]（阶跃主信号） |
| `g_foc.fb.ia/ib/ic` | 三相电流 [A]（静态时应 ≈0，噪声 <0.15A） |
| `g_foc.ref.id` / `iq` | 电流给定 [A]（你写的目标） |
| `g_foc.fb.vbus` | 母线电压 [V]（≈24） |
| `g_foc.fault.all` | 0=无故障；非 0 记录数值回来分析 |
| `g_foc.id_pi.kp / ki` | 复核装载：kp≈0.415（Ls·4000）、ki≈420.5（Rs·4000） |

J-Scope 画曲线（可选但推荐）：`g_debug_snapshot.ia/ib/ic`（float 可加）——阶跃波形直接可视。

## 4. 操作序列

```
① 上电，不启动：state 应=0(STOP)；ia/ib/ic ≈0±0.15A；vbus≈24；fault.all=0
   ——任一不符 → 停，回来报告
② 两步启动（req 语义：START 只开 PWM+写中性占空比，模式执行需 RUN——代码无自动晋升）：
   先写 g_foc.req = 1 (START) → state=1(STARTING)、三相 50% 中性、电机无力
   再写 g_foc.req = 2 (RUN)  → state=2(RUN)、模式开始执行（id/iq 给定仍 0）
③ id 正阶跃：写 g_foc.ref.id = 1.0
   → i_d 快速升至 1A 并稳住；ia/ib/ic 出现 ~0.7A 幅度三相正弦（静止矢量）
④ id 回零：写 g_foc.ref.id = 0 → i_d 回 0
⑤ id 负阶跃：g_foc.ref.id = -1.0 → 对称响应
⑥ 回零，逐步试 2.0、4.0（每次先回零再给新值）
⑦ iq 阶跃（⚠️ 电机会转）：转子固定或清空转向空间后 g_foc.ref.iq = 1.0
   → 电机受力矩，i_q 跟随 1A；若电机开始旋转，回零即可
⑧ 停机：g_foc.req = 0 (STOP)
```

## 5. 通过判据（对照 B 库同参数行为）

| # | 判据 | 量化 |
|---|---|---|
| 1 | 阶跃到达时间 | ibw=4000rad/s（≈636Hz）→ τ≈0.25ms ≈ 5 个控制拍；Watch/JScope 上 1A 阶跃在 **1ms 内到位**（采样显示限制下） |
| 2 | 稳态精度 | 目标 ±10% 内，静差趋势不明显 |
| 3 | 稳定性 | 无持续振荡/啸叫（B 库历史教训：参数不匹配时静止自激顶饱和——出现即停） |
| 4 | 对称性 | +1A 与 -1A 行为一致 |
| 5 | 静态噪声 | id/iq 给定 0 时波动 <0.15A（B 库实测底噪 0.07~0.10A） |
| 6 | 装载复核 | id_pi.kp/ki 与第 3 节数值一致；fault.all 全程 0 |

**B 库行为基准**：B 库用同一套 Rs/L/ibw=4000 在沉沙上做过 d/q 小电流阶跃整定（docs/d轴电流PI阶跃整定、dq电流PI固化与速度回归），其结论为可用且不自激——我们的参数与其逐位一致（test_motor_chensha 锁定），故波形应当可对照。

## 6. 异常处理

| 现象 | 处置 |
|---|---|
| fault.all ≠ 0 | `g_foc.req = 0` → 复位板卡重新上电；把 fault 数值与现象带回来 |
| 静止自激（电流自行增大顶满） | 立即 STOP。这是 B 库踩过的坑（增益与板不匹配）——先复核 kp/ki 装载值，再考虑 ibw 降 2000 重试 |
| 阶跃超调大/振荡 | 记录波形，回来调 ibw（B 库路径：降带宽） |
| id=0 时电流明显非零 | 零偏问题——复位重上电（零偏采集在启动时）；复现则报告 |

## 7. 验收记录要求

结果（含 JScope 截图或 Watch 数值序列、fault 状态、异常现象）带回来 →
全过：关闭关口②，打 `hw-gate2` 标签，进入 P6 drive 层（速度环，关口③）；
不过：按第 6 节排查，我们迭代。

## 附 B：手动对齐流程（Watch 十步，让 iq 真正出力）

> 原理：drag_if（开环电流）模式用自积分角 `ref.theta_e`（上电=0，与编码器无关）定位场——
> spd_r=0 时场角钉死，转子被吸到"真实电角度=0"位置；此时读出编码器-derived 角 δ，
> 则 e_off = -δ (mod 2π)。全程只写 Watch 变量。

```
① 复位上电（state=STOP）
② g_foc.mode.sys  = 0   （debug 模式，确认）
③ g_foc.mode.debug = 1  （drag_if 开环电流）
④ g_foc.ref.spd_r = 0   （场角冻结在 0）
⑤ g_foc.ref.id = 2.0    （iq 保持 0）
⑥ g_foc.req = 1 再写 = 2 （START 开 PWM → RUN 执行 drag_if，转子吸合锁住，保持 2~3 秒）
⑦ 读 g_foc.fb.theta_e → 记为 δ
⑧ g_foc.motor.e_off = (δ < 0.001) ? 0 : (6.2831853 - δ)
⑨ g_foc.mode.debug = 3  （切回 curr_cl 闭环）
⑩ g_foc.req = 1 → g_foc.ref.iq = 1.0 → 电机应出力旋转
   （方向若反：iq 给负验证，方向约定 P6 处理）
注意：e_off 只存 RAM，掉电丢失——正式流程 = P6 的诊断对齐任务（自动并含验收判据）。
```

## 附 C：RUN 后待机"沙沙声"分诊表

上机实录：RUN 且 id=iq=0 时电机有轻微沙沙电流声。机制：零偏在 PWM 关闭时采集
（foc_init 内，target_adc_start 已先行使 JDR 有效——采集时机本身正确），RUN 后
开关注入噪声使有效零偏漂移 → 电流环读到虚拟直流/噪声 → PI 输出小幅差分电压 → 可闻。
B 库同板同电机存在同类现象（其 docs/ADC启动与零偏有效性实施记录、G11 死区补偿
即为此而做——vdead 属 P8 回流资产）。

| 观察项（RUN、零给定） | 判定 | 处置 |
|---|---|---|
| fb.i_d/i_q 噪声 <0.15A，duty 围绕 0.5 抖动 <±0.3% | ✅ B 库基线内（其底噪 0.07~0.10A） | 正常伺服待机噪声，验收不阻断 |
| fb.i_d/i_q 有稳定直流分量 >0.2A | ⚠ PWM-on 零偏漂移 | 记录数值；STOP 对比采样；P6 零偏有效性任务处理 |
| fb.i_d/i_q 噪声 >0.5A 或 duty 大幅摆动 | ❌ 异常 | 立即 STOP，回报波形与数值 |

对比法：req=0（STOP）时记录 i_d/i_q 噪声 → RUN 时再记录 → 差值即开关注入增量。

## 附 A：e_off 说明（电流环验收不用对齐）

id 阶跃验证的是电流环本身——Park 变换用的 theta_e 无论零位在哪，d 轴电流闭环都自洽
（只是"d 轴"指向任意方向）。**速度环（P6）才需要正确的 e_off**（对齐流程届时用诊断子系统
的 MC_DIAG_OWNER_ENCODER_ALIGN 任务，P6 手册展开）。
