### 关键反转（本记录最重要的一课）

审查建议"一行接 conditional"对齐 B 库——**核实 B 库源码后反转**：

```c
/* B 库 foc_drv.c:931-937（spd_curr_cl 主路径） */
foc_vel_feedback(pm, ..., conditional_integral = axdr_observer_adapter_speed_control_active());
    if (conditional_integral && ABS(iq_set)>0)  pdff_ctrl_conditional(...);   // ← 仅观测器接管模式
    else if (ABS(iq_set)>0)                     pdff_ctrl_limited(...);      // ← 编码器反馈真身
    else                                        pdff_ctrl(...);
```

- **编码器反馈速度环（我们的关口③路径）用的是 `pdff_ctrl_limited`**——save/restore 式
  临时收紧 pid 限幅到指令限值，动态积分限幅随之收紧
- conditional 是 B 库**观测器速度接管（无感 H2）专用**，P8 才会用到
- 我 P4 注释"B 库沉沙速度环即用此变体（conditional）"**写错了**，本轮已更正
- 审查的"8~20A windup 窗口"机制描述也不准确：foc_drv.c:448 运行时每拍把
  spd_pi.out_max/min 刷成 ref.iq_max（=±8A），PI 自身限幅实际就是 ±8。
  **真缺口**是 per-command 限幅小于 8A 的场景（如 MIT 给 2A）——PI 仍按 8A 限积分，
  存在 2~8A windup 窗口。这正是 B 库设计 limited 的原由（其注释原文："USB motion
  commands carry a much smaller motor-profile limit"）。

## 4. 过程教训（追加）

1. **审查结论必须核实到源码**：本轮"一行修复"建议若直接执行，会把观测器专用变体接进
   编码器路径——偏离 B 基准且方向相反。审查的价值在发现"没接线"的现象，接什么要查真身。
2. **测试可能把 bug 编码为期望**：三处 count==1 断言就是明证。修行为 bug 时同步排查
   测试期望的"性质"（它是设计意图还是历史行为的快照？）。
3. oracle（legacy 对照件）自身也会有 bug——逐位对照红/绿都要问一句"谁对"。
