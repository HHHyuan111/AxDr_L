## 3. 开发目标与先后关系

### 3.1 主固件功能目标

| 目标 | 希望形成的能力 | 规划时需要讲清 |
|---|---|---|
| VF | 用电压和频率给定展示开环强拖 | 给定、斜坡、角度生成、限制及停止方式 |
| IF | 以电流给定配合开环电角度运行 | 与 VF 的区别，以及电流闭环与角度生成的关系 |
| 电流闭环 | 清楚展示采样、坐标变换、PI、调制和输出 | 反馈有效性、限幅、积分处理及退出条件 |
| 速度闭环 | 在电流环基础上形成速度控制 | 测速、执行周期、速度 PI 与电流给定的衔接 |
| 位置闭环 | 在已有内环基础上形成位置控制 | 位置单位、环绕/多圈语义、轨迹与速度限制 |
| 一个无感算法 | 从观测到最终接入运行的完整路径 | 算法选择、适用工况、启动/切换/失效处理与验证依据 |
| 上位机配套 | 模式、参数、状态、波形与固件语义一致 | 协议兼容、参数回读、数据有效性及用户操作流程 |

这些是目标，不代表每项都已经实现或实机通过。此前提到“今天完成”是当时的期望，本次应按照依赖和验收条件重新排期。

负责人曾问“无感是不是替代这里的角度反馈”。方案应解释角度、速度及其有效性的来源如何选择，以及无感接入对启动状态和保护的影响，不能只增加一个角度变量就称完整无感。

### 3.2 教学路线

已提出的基础课程顺序为：安装包与环境配置 → 课程计划 → 从原理图提取配置依据 → 底层配置及测试 → 控制框架搭建 → VF 强拖 → 电流闭环 → 速度闭环 → 位置闭环 → 控制框架完善；后续扩展 IF 和无感等内容。

代码应支撑逐步讲授，但不要为了教学创建多个长期漂移的算法副本。请提出课程阶段与可运行代码版本如何对应，并说明学生在哪一步观察什么波形、怎样判断本步正确。

### 3.3 上位机的长期方向

上位机希望持续改善示波器、交互与布局，再逐步形成类似 Elmo 的专家整定和教学模块，包括时域、FFT/频域分析及足够采样率的数据获取。负责人重视中文界面、文字对齐、字体一致和示波器尺寸一致，也明确不希望一股脑增加暂时用不到的功能。
