## 2. 从哪里看核心代码

下列路径以固件仓库为基准。

```text
ADC1 注入序列完成
  User/bsp/target_irq.c : HAL_ADCEx_InjectedConvCpltCallback
    → User/app/fast_loop.c : fast_loop_step
       编码器采样 → 角度/位置换算 → 电流/母线采样
    → User/app/control_cycle.c : control_cycle_step
       位置差分测速 → 反馈整理 → Drive → 磁链旁路计算
    → User/drive/drive.c : drive_fast_step
       保护 → STOP/START/RUN → 对齐或运行
    → User/drive/drive_mode.c : drive_mode_step
       V/F、I/F、电流、速度、位置等模式分发
    → User/motor/motor_modes.c / foc_drv.c
       将现有电机上下文转换为控制器输入
    → User/control/foc_control.c : foc_ctrl_step
       坐标变换 → 调节器 → 电压调制
    → User/drive/drive_pwm.c : drive_pwm_commit
       占空比有限值/范围校验 → 相序映射 → Target 写 PWM
    → 快照/周期记录/遥测与观测采样
```

主循环另一条链是 `service_usb_poll → service_scope_route → service_command_dispatch`，负责协议、安全会话和目标下发。CRC、USB 发送在慢路径；硬件快环中保留采样和有界数据拷贝。

三闭环的实际关系：位置误差经位置环得到速度参考，速度误差经速度环得到 Iq 参考，电流误差经 d/q 电流环得到 Vd/Vq，最后调制为三相占空比。电流模式只走内环，速度模式走速度与电流两环，位置模式才走三环。

`foc_control.c` 使用显式输入、状态和输出，不直接访问 HAL。`control_cycle_step` 则仍经 Drive 提交物理 PWM，属于运行编排入口，不能称为完全无副作用的纯算法函数；离线运行依赖硬件替身。

## 4. 需要先处理的问题

### A. 主循环与快环共享命令，缺少整条命令统一生效的边界

证据：`service_command.c:775` 起的速度命令与 `:816` 起的电流命令，在主循环依次修改 `g_foc.mode` 和多个 `g_foc.ref` 字段；本次检查的 USB 分发调用链没有整条命令的临界区或收件箱。ADC 中断读取同一上下文。

结果：源码允许快环在更新中途读到新模式与旧目标的混合组合。单个 float 写入原子性不能保证整条命令一致。已确认结构性风险，未做实机抢占复现，不声称已经发生冲击或失控。

建议：Service 只提交校验后的完整命令；快环在周期入口一次接收并应用，模式切换由 Drive 编排。STOP 保持优先，清除或作废旧运动命令。后续区分“已接收、已应用、实际运行/停止”，不将当前按 req 生成的控制快照等同物理输出状态。

通过标准：在命令每个发布边界安排中断时，快环只能见到整条旧命令或整条新命令；STOP 后旧命令不得重新启动；跨模式切换有明确的控制器清理和启动策略。

### B. 测速窗口有两个边界计算问题

证据：`speed_adapter.c:44` 在只有 window 个样本时就置 ready，但 window 拍差分需要 window+1 个有效时刻；`control_cycle.c` 对无效位置跳过喂入，而测速仍按固定 window/fs 计算时间。

本轮直接编译生产 `speed_adapter.c`，结果：

| 输入 | 期望 | 实际输出 |
|---|---:|---:|
| 初始化后连续两次位置 1 rad、20 kHz | 0 rad/s | 第二次 10000 rad/s |
| 同一静止输入第三次 | 0 rad/s | 0 rad/s |
| 匀速每拍 0.001 rad、20 kHz | 20 rad/s | 连续正常输入 20 rad/s |
| 上述匀速中跳过一拍，再恢复输入 | 20 rad/s | 30 rad/s |

这是估算器边界复现；不能直接认定上电 PWM 开启时发生跳变，亦未证明当前 ABZ 实机发生过无效拍。现有测试检查稳定窗口、跨零和丢样当拍冻结，没有覆盖恢复拍。

建议：初始化满足完整历史后再置有效；用真实周期序号计算间隔，或明确丢样后重建窗口。测速状态放入显式上下文，避免多个回放实例共享文件静态状态。

通过标准：任意合法初始静止角度无虚假速度；丢样恢复不缩短时间分母；跨圈、重新初始化及独立实例不串状态。

### C. 编码器被当作所有模式的共同前提

证据：`drive.c:85` 的保护统一以编码器位置有效性作为位置/速度有效性；`:373` 的 START 对未对齐 ABZ 统一进入对齐。`position_adapter.c` 拒绝非编码器来源。

当前有感配置可以沿用这套逻辑；直接追加无感角度变量不能解决依赖。上位机现有合同还明确 V/F、I/F 不要求编码器对齐，这与固件的统一 START 行为需要在接通协议前统一。

建议：按模式定义所需测量及保护条件，独立保存编码器实测、虚拟角度、估算角度/速度及其有效性，明确选择控制使用哪一个。取消某模式对编码器的依赖时，必须同时设计失步/失锁退出条件，不能简单删除保护。

通过标准：V/F、I/F 不意外进入编码器对齐；有感闭环仍要求有效标定；无感未锁定时不能被选作控制反馈；位置闭环不能误把开环积分角当实测位置。

## 5. 应保留与逐步整理的结构

- 保留：纯 FOC 控制层、限幅和级联调节、Drive 统一启停、PWM 提交校验。每拍 `pwm_cmd.valid` 重新清零，无有效计算会停止，不能把模式 wrapper 返回 true 直接误判为沿用旧 PWM 的漏洞。
- 渐进整理：宽 `foc_t`、Motor wrapper 对 Drive PWM 的反向调用、全局 `g_obs` 与静态测速状态。先为新增职责建立窄接口，不全库改名或一次拆完 `common.h`。
- 有效性缺口：快环 `vbus_valid=true` 固定赋值，Target 直接读 ADC2 JDR1；当前接口未表达母线采样是否新鲜。温度反馈明确无效，不能把过温保护列为已完整接入。需分别确认硬件采样合同，不能凭此断言 ADC 当前故障。
- 文档漂移：旧导读仍包含 MT6816 和旧构建范围描述，测速头文件仍称“影子链”，当前速度反馈实际上已使用该输出。后续以实际编译清单和源码更新导读。
- 资源预算：10/28 报告的 RW_IRAM1（含 RamFunc）为 78024/131072 B，仅为历史构建数据。20 kHz 每周期只有 50 μs；此前停机采集耗时不代表加入三环、观测器和采集后仍有余量。

## 7. 接下来按四个交付点推进

| 顺序 | 固件工作 | 上位机对应工作 | 放行条件 |
|---|---|---|---|
| 1. 稳定运行边界 | 修测速边界；完整命令提交；模式切换/停止优先；冻结现有有感基线 | 显示请求状态和实际状态，继续使用原页面 | 定向故障/抢占/切换检查；板端操作前重新完成身份和停止预检 |
| 2. 接通 V/F 与 I/F | 补两个 USB 入口；定义虚拟角度、启动/斜坡/限幅/停止；按模式处理对齐依赖 | 复用既有页面，能力、字段、单位、回读一致 | 启停/正反转/斜坡/断连；区分设定频率与实测转速，禁止用变量写入代替验收 |
| 3. 三闭环完整交付 | 保留电流/速度实现，补位置命令、参考坐标、速度和电流限制及轨迹 | 同一操作流程完成电流、速度、位置选择与状态回读 | 分环小目标、正反向、限幅、停止、切换验证；通过后再组合运行 |
| 4. 单一无感方案 | 建议从反电动势 SMO+PLL 候选起步：先旁路角度/速度估计，再 I/F 起动、可信度判定、平滑切换及失锁停机 | 增加估算角/速度、与编码器误差、控制源、起动/锁定/故障状态 | 先用编码器作对照，确认时间对齐和有效速度区间，再允许接管；实机测完整快环耗时 |

第四步算法选型仍需核对电机参数、实际电压重构和已有参考实现；不是已经批准的完整无感设计。首版目标限定中速段无感速度控制，不承诺静止位置保持、零速带载或无感位置伺服。普通反电动势法低速信号不足，不能用增加一个菜单解决。

今天目标可以按上述顺序推进，但“完整实现并实机通过”取决于每一关数据，不能用页面出现、单元测试通过或旁路观测代替最终验收。下一次最小实施范围建议先锁定第 1 项，再接通已有模式，不继续增加新的专家分析功能。
